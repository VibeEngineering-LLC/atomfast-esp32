Ты пишешь фрагмент C для вклейки в файл `main/web_server.c` прошивки ESP32 (ESP-IDF 5.4, HTTP-сервер `esp_http_server`, C11, `-Werror=frame-larger-than=3584`: ни одна функция не должна держать на стеке больше ~1500 байт). Верни ТОЛЬКО код C (четыре обработчика), без пояснений и без markdown-ограждений. Комментарии короткие, по-русски. Фрагмент вклеивается внутрь файла, где уже есть (не объявляй заново):
- `static bool csrf_check(httpd_req_t *req)` — проверяет заголовок X-CSRF-Token; при неуспехе САМА шлёт 403 и возвращает false (тогда обработчик должен вернуть `ESP_FAIL`).
- `static esp_err_t sens_reply_err(httpd_req_t *req, const char *status, const char *code)` — шлёт `{"ok":false,"err":"<code>"}` со статусом-строкой (например "400 Bad Request") и возвращает ESP_FAIL.
- `static int sens_read_body(httpd_req_t *req, char *buf, size_t cap)` — читает всё тело запроса в buf (возвращает длину; -1 если тело пустое, не помещается (длина >= cap) или обрыв); завершающий NUL не ставит.
- Заголовки уже подключены: `esp_http_server.h`, `esp_heap_caps.h`, `cJSON.h`, `<string.h>`, `<stdio.h>`, `<stdlib.h>`, `af_push_drv.h`.
Из `af_push_drv.h`/`af_push.h`: `af_push_cfg_t`, `af_push_cmd_t`, `void af_push_get_cfg(af_push_cfg_t *out)`, `int af_push_apply(const af_push_cmd_t *cmd)` (0 принято; -1 не готов; -2 NVS не записан, действует до перезагрузки), `int af_push_get_json(char *buf, size_t cap)` (длина или -1), `int af_push_test_start(void)` (0 запущен; -1 уже идёт; -2 нет адреса/токена; -3 не готов), `int af_push_reset(void)` (0 ок; -1 не готов), `int af_push_parse(const char *body, size_t n, const af_push_cfg_t *cur, af_push_cmd_t *cmd)` (0 или код: AF_PUSH_E_BODY=-1, AF_PUSH_E_JSON=-2, AF_PUSH_E_KEY=-3, AF_PUSH_E_VALUE=-4, AF_PUSH_E_INCOMPLETE=-5), `int af_sens_body_ok(const char *buf, size_t n)` (1 если тело годится: без обратной косой, NUL, управляющих символов и не-ASCII).

## Обработчики (имена обязательны; все `static esp_err_t name(httpd_req_t *req)`)
1. `handle_push_get` — GET /api/push: выделить буфер 2048 байт `heap_caps_malloc(2048, MALLOC_CAP_SPIRAM | MALLOC_CAP_8BIT)`, при NULL — `malloc(2048)`; если и это NULL — `httpd_resp_send_err(req, HTTPD_500_INTERNAL_SERVER_ERROR, "oom")` и вернуть ESP_FAIL. `n = af_push_get_json(buf, 2048)`; n < 0 → free, `httpd_resp_send_err(req, HTTPD_500_INTERNAL_SERVER_ERROR, "json")`, вернуть ESP_FAIL. Иначе `httpd_resp_set_type(req, "application/json")`, `httpd_resp_set_hdr(req, "Cache-Control", "no-store")`, `e = httpd_resp_send(req, buf, n)`, free(buf), вернуть e.
2. `handle_push_post` — POST /api/push (сохранить настройки): `if (!csrf_check(req)) return ESP_FAIL;`. `char body[384]; int n = sens_read_body(req, body, sizeof body); if (n < 0) return sens_reply_err(req, "400 Bad Request", "bad_body");`. `af_push_cfg_t cur; af_push_get_cfg(&cur); af_push_cmd_t cmd; int pc = af_push_parse(body, (size_t)n, &cur, &cmd);` При pc != 0: затереть cur и cmd (`memset(&cur, 0, sizeof cur); memset(&cmd, 0, sizeof cmd);`) и ответить: AF_PUSH_E_BODY → `sens_reply_err(req, "400 Bad Request", "bad_body")`; AF_PUSH_E_JSON → "json" (400); AF_PUSH_E_KEY → "unknown_key" (400); AF_PUSH_E_VALUE → "bad_value" (400); AF_PUSH_E_INCOMPLETE → `"409 Conflict"`, "incomplete"; иное → 400 "bad_value". При успехе: `int rc = af_push_apply(&cmd);` затереть cur и cmd (memset 0); rc == -1 → `sens_reply_err(req, "503 Service Unavailable", "not_ready")`; иначе ответ `{"ok":true,"persisted":true}` (rc == 0) или `{"ok":true,"persisted":false}` (rc == -2): `httpd_resp_set_type(req, "application/json"); httpd_resp_sendstr(req, ...); return ESP_OK;`. Токен нигде не печатать и не логировать.
3. `handle_push_test` — POST /api/push/test (пробный запрос, асинхронный): csrf_check как выше; если `req->content_len > 0` — прочитать тело `char tb[64]` через sens_read_body; n < 0 → `sens_reply_err(req, "400 Bad Request", "bad_body")`; тело допустимо только `{}` (после проверки `af_sens_body_ok` сравнить `n == 2 && memcmp(tb, "{}", 2) == 0`), иначе тот же 400 "bad_body". `int rc = af_push_test_start();` rc == 0 → `httpd_resp_set_status(req, "202 Accepted"); httpd_resp_set_type(req, "application/json"); httpd_resp_sendstr(req, "{\"ok\":true,\"started\":true}"); return ESP_OK;`; rc == -1 → `sens_reply_err(req, "409 Conflict", "busy")`; rc == -2 → `"409 Conflict"`, "incomplete"; иначе → `"503 Service Unavailable"`, "not_ready".
4. `handle_push_reset` — POST /api/push/reset (сбросить курсоры, «отправлять с начала»; нужно явное подтверждение в теле): csrf_check; `char rb[64]; int n = sens_read_body(req, rb, sizeof rb);` n < 0 → 400 "bad_body"; `if (!af_sens_body_ok(rb, (size_t)n)) return sens_reply_err(req, "400 Bad Request", "bad_body");` Разобрать `cJSON *root = cJSON_ParseWithLength(rb, (size_t)n);` NULL или не объект → (удалить если не NULL) 400 "json". `const cJSON *c = cJSON_GetObjectItemCaseSensitive(root, "confirm");` Подтверждение есть, только если `cJSON_GetArraySize(root) == 1 && cJSON_IsTrue(c)`; иначе cJSON_Delete(root) и `sens_reply_err(req, "400 Bad Request", "confirm_required")`. Иначе cJSON_Delete(root); `int rc = af_push_reset();` rc != 0 → `"503 Service Unavailable"`, "not_ready"; иначе ответ `{"ok":true}` (тип application/json, `httpd_resp_sendstr`), вернуть ESP_OK.
