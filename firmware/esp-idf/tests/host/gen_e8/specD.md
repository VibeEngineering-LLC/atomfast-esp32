## Внутреннее устройство
Константы: `#define PUSH_TASK_STACK 5120`, `#define PUSH_NVS_NS "afpush"`, ключи `"push_cfg"` (blob af_push_cfg_t в раскладке cfg_encode, 152 байта) и `"push_cur"` (blob 48 байт, курсоры). `static const char *TAG = "af_push";`.
Состояние (всё static): мьютекс `s_mtx` (SemaphoreHandle_t; защищает s_cfg, s_ring, s_auth_stop, s_test, s_test_req, s_running, s_dirty); `af_push_cfg_t s_cfg`; `af_push_ring_t s_ring[3]`; `uint8_t s_auth_stop`; `af_push_test_t s_test`; `uint8_t s_test_req`; `int s_running` (задача существует); `volatile int s_sending`; `bool s_dirty` (курсоры изменились и не сохранены); `uint32_t s_last_save_ms`; `TaskHandle_t s_task`; `volatile uint32_t s_stack_hwm`; `uint8_t s_logged_err[3]`.

Слабая заглушка журнала (дословно): `__attribute__((weak)) void af_log_event(int level, const char *src, const char *msg) { (void)level; (void)src; (void)msg; }` — реальную даёт другой модуль; вызывай `af_log_event(level, "push", "строка-литерал")` ТОЛЬКО со строками-литералами (никаких токенов, паролей, адресов, MAC в сообщениях), и только при смене состояния (когда ошибка кольца стала другой, чем в s_logged_err[kind]; при возврате к норме — один раз "ok"), уровни: 1 инфо, 2 предупреждение.

Функции (все static, кроме публичного API):
1. `now_ms()` — `(uint32_t)(esp_timer_get_time() / 1000)`. `now_ts()` — time(NULL), если < 1700000000 вернуть 0.
2. `cfg_load()` — открыть NVS READONLY; прочитать blob "push_cfg" (длина через nvs_get_blob с буфером 152 байта; размер должен быть ровно 152, иначе считать повреждённым) → `af_push_cfg_decode(&s_cfg, buf, len)`; ошибка/нет ключа — af_push_cfg_default. Затем blob "push_cur" (48 байт) → `af_push_curs_decode(cur, ...)`; результат раздать в s_ring[i].cur. Для i=0..2 `af_push_ring_init(&s_ring[i], s_cfg.batch_rows)` ДО раздачи курсоров. Буферы — на стеке (<=160 байт).
3. `cfg_save(const af_push_cfg_t *c)` → int (0 ок, -1 ошибка): encode в буфер 152, nvs_open READWRITE, nvs_set_blob, nvs_commit, nvs_close.
4. `curs_save_locked()` — (вызывается при взятом s_mtx) encode курсоров из s_ring[i].cur в буфер 48, записать blob "push_cur" (open, set_blob, commit, close); при успехе s_dirty=false, s_last_save_ms=now_ms(). Возврат 0/-1. NVS-вызовы под мьютексом допустимы (они короткие).
5. `src_info(int kind, uint32_t *oldest, uint32_t *head, uint32_t *epoch)` — `af_hq_params_t hp; af_hq_init(&hp); hp.kind = kind; af_hq_plan_t pl; int rc = af_store_plan(&hp, &pl, head, epoch); *oldest = pl.start;` вернуть rc (0 ок, -1 занят, -2 нет кольца).
6. `src_read(void *ctx, int kind, uint32_t since, void *out, uint32_t max, uint32_t *next, uint32_t *lost)` — обёртка над af_store_read, ctx не используется; сигнатура совместима с af_push_read_fn.
7. HTTP: структура `typedef struct { char buf[160]; size_t n; } resp_t;` и обработчик событий `static esp_err_t http_ev(esp_http_client_event_t *evt)`: на HTTP_EVENT_ON_DATA дописывать evt->data (до evt->data_len) в ((resp_t*)evt->user_data)->buf с ограничением на размер 159 (лишнее отбросить).
   `static esp_err_t do_post(const af_push_cfg_t *c, int kind, const char *mac, uint32_t head, uint32_t epoch, uint32_t first_seq, uint32_t lost, const char *body, size_t len, int *http, resp_t *rs)` — создаёт клиент `esp_http_client_init` с конфигом: `.host=c->host, .port=c->port, .path=af_push_path(kind), .transport_type=HTTP_TRANSPORT_OVER_TCP, .method=HTTP_METHOD_POST, .timeout_ms=(int)c->timeout_s*1000, .buffer_size=512, .buffer_size_tx=768, .disable_auto_redirect=true, .keep_alive_enable=false, .event_handler=http_ev, .user_data=rs`. Если init вернул NULL — вернуть ESP_ERR_NO_MEM. Заголовки через esp_http_client_set_header: "Content-Type" = "text/csv"; "Authorization" = "Bearer " + токен (собери в локальный буфер char auth[80] через snprintf, длина гарантированно влезает); заголовки X-AF-* из `af_hq_hdrs_fill(&hh, kind, head, epoch, first_seq, lost, mac)`: "X-AF-Device"=hh.device (только если hh.device[0] != 0), "X-AF-Ring"=hh.kind, "X-AF-Epoch"=hh.epoch, "X-AF-First-Seq"=hh.first_seq, "X-AF-Lost"=hh.lost. Затем `esp_http_client_set_post_field(cl, body, (int)len)`, `err = esp_http_client_perform(cl)`; `*http = (err == ESP_OK) ? esp_http_client_get_status_code(cl) : 0`; `esp_http_client_cleanup(cl)`; rs->buf завершить нулём. Токен НИКОГДА не логировать, никаких ESP_LOG с auth/cfg->token. Перед вызовом обнулить rs->n и rs->buf[0].
8. Колбэки для общей логики `af_push_send_ring` (она уже написана в af_push.h): тип `af_push_ops_t {info, read, post, now_ts}` (info: `int (*)(void *ctx, int kind, uint32_t *oldest, uint32_t *head, uint32_t *epoch)`; read: `af_push_read_fn`; post: `int (*)(void *ctx, int kind, const char *mac, uint32_t head, uint32_t epoch, uint32_t first_seq, uint32_t lost, const char *body, size_t len, int *http, char *resp, size_t resp_cap)`; now_ts: `uint32_t (*)(void *ctx)`), макросы возврата `AF_PUSH_S_OK 0 / AF_PUSH_S_IDLE 1 / AF_PUSH_S_WAIT 2 / AF_PUSH_S_STOP 3`, функция `int af_push_send_ring(const af_push_ops_t *ops, void *ctx, int kind, const af_push_cfg_t *c, const char *mac, af_push_ring_t *r, uint8_t *auth_stop, char *body, size_t cap, uint32_t *pending_left, int *cursor_moved)`.
   Напиши: `static int cb_info(void *ctx, int kind, uint32_t *o, uint32_t *h, uint32_t *e)` (вызывает src_info), `static int cb_post(void *ctx, int kind, const char *mac, uint32_t head, uint32_t epoch, uint32_t first_seq, uint32_t lost, const char *body, size_t len, int *http, char *resp, size_t resp_cap)` — ctx это `const af_push_cfg_t *`; вызывает do_post с локальным `resp_t rs`, на время вызова `s_sending = 1` (затем 0), копирует rs.buf в resp (не более resp_cap-1, завершить нулём); возвращает 0 если do_post вернул ESP_OK, иначе 1; `static uint32_t cb_now(void *ctx)` (now_ts()); `static const af_push_ops_t s_ops = { cb_info, src_read, cb_post, cb_now };` (src_read имеет сигнатуру af_push_read_fn).
   Добавь счётчик поколений `static uint32_t s_gen;` (меняется под мьютексом при apply и reset).
   `static int send_ring(int kind, const af_push_cfg_t *c, char *body, size_t body_cap, uint32_t *pending_left)` → int (значения AF_PUSH_S_*):
   a. Под мьютексом: `gen0 = s_gen; af_push_ring_t r = s_ring[kind]; uint8_t auth = s_auth_stop;`.
   b. `char mac[24] = {0}; (void)ble_gw_target_mac(mac, sizeof mac);` (если вернуло <= 0, mac останется пустым — af_push_send_ring сама поставит ошибку NODEV).
   c. `int moved = 0; int res = af_push_send_ring(&s_ops, (void *)c, kind, c, mac, &r, &auth, body, body_cap, pending_left, &moved);`
   d. Под мьютексом: если `gen0 == s_gen` — `s_ring[kind] = r; if (auth) s_auth_stop = 1; if (moved) s_dirty = true;` иначе (за время отправки настройки/курсоры сброшены) результат отбросить: `*pending_left = 0; res = AF_PUSH_S_WAIT`. Тут же скопировать `err = r.err`.
   e. Журнал: если gen совпал и err != s_logged_err[kind] — вызвать af_log_event с литералом по коду ошибки (AUTH: "auth failed", BAD: "batch rejected", NET: "network error", SRV: "server error", BIG: "batch too big", PROTO: "bad response", HTTP4: "http error", NODEV/NOSTORE/OOM: "internal error", err==0: "ok"), уровни: err==0 → 1, прочее → 2; затем `s_logged_err[kind] = err`.
   f. Вернуть res.
9. `run_test()` — выполняется задачей: под мьютексом скопировать s_cfg; вне мьютекса: mac как в (b) (нет mac — результат err=NODEV); body = char[200] на стеке, `n = af_push_test_body(body, sizeof body)`; `t0 = esp_timer_get_time()`; `do_post(&c, AF_HQ_KIND_ENV, mac, 0, 0, 0, 0, body, n, &http, &rs)`; `ms = (esp_timer_get_time()-t0)/1000`. Итог в s_test под мьютексом: state=2, http, ms, ts=now_ts(); accepted = -1, а при http==200 и успешном af_push_parse_resp — accepted значение; err: transport ошибка → AF_PUSH_ERR_NET; 200 с успешным разбором → 0; 200 без разбора → PROTO; 401 → AUTH; 400 → BAD; 413 → BIG; 5xx/408/429 → SRV; прочие 4xx → HTTP4; остальное → PROTO. Курсоры и s_auth_stop тест НЕ трогает. В конце s_test_req = 0.
10. `push_task(void *arg)` — главная задача. Локальные: `size_t cap = AF_PUSH_BODY_MAX; char *body = heap_caps_malloc(cap, MALLOC_CAP_SPIRAM | MALLOC_CAP_8BIT); if (!body) { cap = 4096; body = malloc(cap); }`. Если body == NULL: под мьютексом всем кольцам err = AF_PUSH_ERR_OOM, затем `s_running = 0`, `s_task = NULL`, vTaskDelete(NULL) (без возврата). Цикл `for(;;)`:
   - под мьютексом: `c = s_cfg`, `treq = s_test_req`, `auth = s_auth_stop`. Если `!c.enabled && !treq`: если s_dirty — curs_save_locked(); `s_running = 0; s_task = NULL;` отпустить мьютекс; free(body); vTaskDelete(NULL). (Решение о выходе и s_running=0 принимать под одним удержанием мьютекса.)
   - `s_stack_hwm = uxTaskGetStackHighWaterMark(NULL);`
   - если treq: run_test(); continue.
   - если `!wifi_is_connected() || ota_busy_is_busy()`: ожидание 5000 мс через `ulTaskNotifyTake(pdTRUE, pdMS_TO_TICKS(5000))`; continue.
   - если auth: ожидание уведомления 30000 мс; continue (снимается af_push_apply/af_push_reset).
   - обход колец kind=0..2 (если бит маски c.rings не установлен — пропуск): `rc = send_ring(kind, &c, body, cap, &left)`; накапливать: `any_more |= (left > 0)`; `any_fail |= (rc == AF_PUSH_S_WAIT)`; `any_stop |= (rc == AF_PUSH_S_STOP)`. Если rc == AF_PUSH_S_OK и left > 0 — НЕ ждать, остаток уйдёт на следующем круге после короткой паузы. Между кольцами `vTaskDelay(pdMS_TO_TICKS(50))` (отдать CPU). Если после очередной отправки `s_auth_stop` стал 1 — прервать обход.
   - сохранение курсоров: под мьютексом `if (af_push_curs_due(s_dirty, now_ms(), s_last_save_ms)) curs_save_locked();`
   - расчёт паузы (мс): `rnd = esp_random() & 0xFF`; максимальное `fails` среди включённых колец (под мьютексом); если max_fails > 0 → `wait = af_push_backoff_ms(max_fails, rnd)`; иначе `wait = af_push_pause_ms(any_more ? 1 : 0, c.interval_s, rnd)`. Если any_fail, а max_fails == 0 (занято, нет mac) — wait = 3000.
   - `ulTaskNotifyTake(pdTRUE, pdMS_TO_TICKS(wait))`.
11. `spawn_locked()` — вызывать при взятом мьютексе: если `!s_running && (s_cfg.enabled || s_test_req)`: `xTaskCreate(push_task, "af_push", PUSH_TASK_STACK, NULL, 2, &s_task) == pdPASS` → s_running = 1; иначе ESP_LOGE(TAG, "task create failed") и s_test_req = 0, s_test.state = 2, s_test.err = AF_PUSH_ERR_OOM.
12. `wake()` — если s_task != NULL: xTaskNotifyGive(s_task) (читать s_task под мьютексом или вызывать при взятом мьютексе).

## Публичный API
- `void af_push_start(void)`: создать мьютекс (при ошибке — ESP_LOGE и выход), `cfg_load()`, под мьютексом `spawn_locked()`.
- `void af_push_get_cfg(af_push_cfg_t *out)`: копия s_cfg под мьютексом (если out == NULL или мьютекса нет — default).
- `int af_push_apply(const af_push_cmd_t *cmd)`: -1 если cmd NULL или мьютекса нет. Под мьютексом: `s_cfg = cmd->cfg; s_gen++`; для каждого кольца `af_push_ring_clear_err` (с s_cfg.batch_rows); если `cmd->dest_changed` — `af_push_ring_reset_cursor` для каждого кольца и s_dirty = true; `s_auth_stop = 0`; затем `spawn_locked(); wake();`. Вне мьютекса: `rc = cfg_save(&cmd->cfg)`; если dest_changed — под мьютексом `curs_save_locked()`. Вернуть 0, либо -2 если cfg_save не удался.
- `int af_push_get_json(char *buf, size_t cap)`: под мьютексом собрать `af_push_view_t v` (memset 0; sending = s_sending; auth_stop; stack_hwm = s_stack_hwm; now_ts = now_ts(); ring[] = s_ring[]; test = s_test) и копию конфига; отпустить; вне мьютекса для kind 0..2 вызвать src_info и при rc == 0 заполнить v.info[kind] {present=1, oldest, head, epoch}; вернуть `af_push_json(buf, cap, &cfg, &v)`. `af_push_view_t` и `af_push_cfg_t` держать на стеке (около 400 и 160 байт).
- `int af_push_test_start(void)`: -3 нет мьютекса; под мьютексом: -1 если `s_test.state == 1`; -2 если `s_cfg.host[0] == 0 || s_cfg.token[0] == 0`; иначе `memset(&s_test,0,sizeof s_test); s_test.state = 1; s_test.accepted = -1; s_test_req = 1; spawn_locked(); wake();` вернуть 0.
- `int af_push_reset(void)`: -1 нет мьютекса; под мьютексом: `s_gen++`; для каждого кольца `af_push_ring_reset_cursor(&s_ring[i], s_cfg.batch_rows)`; `s_auth_stop = 0`; s_dirty = true; `curs_save_locked()`; `wake()`; вернуть 0.

Следи за размером кадров стека: ни одна функция не должна держать на стеке массивы больше 400 байт (кроме af_push_json, af_push_pack — они уже написаны). Проверяй возврат xSemaphoreTake(..., portMAX_DELAY). Не используй malloc в горячем пути, кроме единственного буфера тела в начале задачи.
