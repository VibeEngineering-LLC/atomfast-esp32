Кольца: kind 0 raw, 1 agg, 2 env; кольцо `ST.ring[k]` — `af_ring_t` (поля seq, epoch; `af_ring_clear(&ring)` увеличивает epoch; `af_ring_push(&ring, rec)`), запись raw кодируется `af_raw_encode(&rec, buf20)`.

## Глобальные объекты и вспомогательные функции (напиши)
```
static store_t ST;
static char BODY[16384];
static int G_PORT;
static const char *G_TOKEN;
```
- `static int http_req(int port, const char *method, const char *path, const char *hdrs, const char *body, size_t blen, int *status, char *resp, size_t rcap)` — HTTP/1.1 клиент поверх сокетов: connect на 127.0.0.1:port; таймауты SO_RCVTIMEO и SO_SNDTIMEO по 5 с; отправить `METHOD path HTTP/1.1\r\nHost: 127.0.0.1\r\nConnection: close\r\nContent-Length: <blen>\r\n` + hdrs (если не NULL; строки заканчиваются "\r\n") + `\r\n` + тело; прочитать ответ до закрытия соединения (EOF/ошибка/таймаут); если прочитано 0 байт или нет строки статуса `HTTP/1.x <код>` — вернуть -1 и *status=0; иначе *status = код, тело ответа (после `\r\n\r\n`) скопировать в resp (до rcap-1 байт, завершить нулём) и вернуть 0. Закрыть сокет. SIGPIPE игнорировать (`signal(SIGPIPE, SIG_IGN)` в main; подключи `<signal.h>`).
- `static void ctl(const char *path)` — `http_req(G_PORT, "POST", path, NULL, "", 0, &st, tmp, sizeof tmp)`; проверить `CHECK(st == 200)`.
- `static cJSON *stats(void)` — GET `/ctl/stats` (метод "GET", тело пустое), вернуть `cJSON_Parse(resp)` (resp — static буфер 262144 байт; при ошибке вернуть NULL после CHECK(0)).
- `static int srows(cJSON *s, const char *ring)` — `rows.<ring>` из статистики; `static int sacc(cJSON *s, const char *ring)` — `accepted_sum.<ring>`; `static int smax(cJSON *s, const char *ring)` — `max_seq.<ring>`; `static int smin(cJSON *s, const char *ring)` — `min_seq.<ring>`; `static int sposts(cJSON *s)` — число элементов массива `posts`; `static int spost_int(cJSON *s, int i, const char *key)` — целое поле key у i-го элемента posts (если поля нет — -999); `static const char *spost_ring(cJSON *s, int i)` — строка поля "ring" i-го элемента.
- `typedef struct { int port; const char *token; store_t *st; } ig_t;` и колбэки: `ig_info`/`ig_read` — обёртки над fk_info/fk_read с ctx=ig_t* (используют `((ig_t*)ctx)->st`); `static uint32_t ig_now(void *ctx)` — вернуть 1792860000; `static int ig_post(...)` (сигнатура ops->post) — собрать заголовки так же, как это делает прошивка: `af_hq_hdrs_t hh; af_hq_hdrs_fill(&hh, kind, head, epoch, first_seq, lost, mac);` затем строка заголовков `Authorization: Bearer <token>\r\nContent-Type: text/csv\r\nX-AF-Device: <hh.device>\r\nX-AF-Ring: <hh.kind>\r\nX-AF-Epoch: <hh.epoch>\r\nX-AF-First-Seq: <hh.first_seq>\r\nX-AF-Lost: <hh.lost>\r\n`; вызвать `http_req(g->port, "POST", af_push_path(kind), hdrs, body, len, http, resp, resp_cap)`; вернуть 0 если http_req вернул 0, иначе 1 (тогда *http=0). `static const af_push_ops_t IG_OPS = { ig_info, ig_read, ig_post, ig_now };`
- `static af_push_cfg_t icfg(uint16_t batch, uint8_t rings)` — default; enabled=1; host="10.1.2.3"; token="x"; batch_rows=batch; rings=rings.
- `static int drive(ig_t *g, const af_push_cfg_t *c, af_push_ring_t r[3], uint8_t *auth, int max_steps)` — имитация цикла задачи без пауз: до max_steps итераций; в каждой итерации для kind=0..2 (если бит маски c->rings установлен): `res = af_push_send_ring(&IG_OPS, g, kind, c, D1_MAC, &r[kind], auth, BODY, sizeof BODY, &left, &moved)`; считать `progress` если res == AF_PUSH_S_OK или res == AF_PUSH_S_WAIT; если после какого-либо вызова `*auth != 0` — немедленно вернуть число сделанных итераций; если за итерацию ни одно кольцо не вернуло OK или WAIT (все IDLE/STOP) — выйти из цикла. Вернуть число итераций.
- `static void setup(int nraw, int nagg, int nenv)` — `ld_all(); st_init(&ST, 1300, 400, 400); st_fill(&ST, nraw, nagg, nenv); ctl("/ctl/reset_db"); ctl("/ctl/maxbody?v=65536");`.

## Сценарии (имена функций обязательны; все — `static void i_имя(void)`; в main — RUN для каждого в порядке ниже)
Общее: в каждом сценарии `ig_t g = { G_PORT, G_TOKEN, &ST }`; кольцо r[3] инициализируется `af_push_ring_init(&r[k], batch)`; `uint8_t auth = 0`; stats() освобождать `cJSON_Delete`. «Сверка» = сравнение чисел из stats() с ожидаемыми.
1. `i_full_delivery` — setup(1200, 365, 291); c = icfg(100, 7); drive(max_steps=200). Сверка: rows raw==1200, agg==365, env==291; accepted_sum равна rows по каждому кольцу; max_seq raw==1199, agg==364, env==290; min_seq всех колец 0; r[k].cur.acked == n-1 и cur.valid==1 и cur.epoch==21; r[k].stopped==0 и r[k].err==0; все посты в журнале: status==200 и inj==0 (spost_int(..., "inj") — в JSON это булево, поэтому для поля inj проверяй через cJSON напрямую: false); число постов raw==12, agg==4, env==3; `hardware`==1.
2. `i_big_batch` — setup(1200,0,0); c = icfg(2000, 1); r.eff_batch=2000; drive(max 100): rows raw==1200; каждый пост: len <= 16384 и status==200; число постов raw от 6 до 9 включительно.
3. `i_retry_5xx` — setup(300,0,0); c = icfg(50, 1); ctl("/ctl/fault?kind=code&code=503&n=2"); drive(max 100): rows raw==300; посты 0,1,2 имеют status 503, 503, 200 и одинаковый first_seq==0 (первые три записи журнала); r[0].fail_total==2; r[0].retries==2; r[0].fails==0; accepted_sum raw==300.
4. `i_retry_drop` — setup(300,0,0); c = icfg(50, 1); ctl("/ctl/fault?kind=drop&n=2"); drive: посты 0,1,2: status 0, 0, 200; first_seq у всех трёх одинаковый (0); rows raw==300; accepted_sum raw==300; r[0].fail_total==2.
5. `i_commit_drop` — setup(300,0,0); c = icfg(50, 1); ctl("/ctl/fault?kind=commit_drop&n=1"); drive: пост 0 (committed, ответ не дошёл): status 0; пост 1 имеет тот же first_seq (0), status==200 и accepted==0 (идемпотентный повтор: приёмник уже записал) и last_seq==49; rows raw==300; max_seq raw==299; accepted_sum raw==250 (первая пачка записана, но подтверждение потеряно); r[0].cur.acked==299.
6. `i_auth_401` — setup(300,0,0); c = icfg(50, 1); ctl("/ctl/token?v=other-token-0123456789"); drive(max 50): auth==1 после первого же вызова; число постов ==1 и его status==401; rows raw==0; r[0].err==AF_PUSH_ERR_AUTH; затем ctl("/ctl/token?v=<G_TOKEN>") (строка собирается в буфере), auth=0, af_push_ring_clear_err(&r[0], 50); drive(max 100): rows raw==300.
7. `i_bad_400` — setup(300,200,0); c = icfg(50, 3); ctl("/ctl/fault?kind=code&code=400&n=1"); drive(max 100): ring raw остановлен (r[0].stopped==1, r[0].err==AF_PUSH_ERR_BAD), кольцо agg доставлено полностью (rows agg==200); журнал: ровно один пост по raw и он status 400; ещё один drive(max 20) не добавляет постов по raw (число постов raw прежнее); затем af_push_ring_clear_err(&r[0], 50), drive(max 100): rows raw==300. Отдельно (контракт приёмника): ручной POST через http_req на "/ingest/raw" с заголовками Authorization Bearer G_TOKEN, X-AF-Device D1_MAC, X-AF-Epoch 21, X-AF-First-Seq 5, X-AF-Lost 0 и телом = первая пачка из BODY (первая строка данных с seq 0) → status==400 (first_seq не совпадает с первой строкой). Для этого заранее собери тело через af_push_pack (аргументы: fk_read, &ST, 0, 0, 10, D1_MAC, 21, 0, BODY, sizeof BODY, &pk).
8. `i_413_shrink` — setup(300,0,0); c = icfg(200, 1); r.eff_batch=200; ctl("/ctl/maxbody?v=3000"); drive(max 200): rows raw==300; первый пост status==413; r[0].fail_total>=1; r[0].eff_batch >= 25 в конце (после успешных пачек растёт); все посты со status 200 имеют len <= 3000 (поле len); в конце ctl("/ctl/maxbody?v=65536").
9. `i_reset_resend` — setup(300,0,0); c = icfg(100, 1); drive(max 100) → rows raw==300; n0 = sposts; af_push_ring_reset_cursor(&r[0], 100); drive(max 100): новые посты: ровно один (sposts == n0+1), его first_seq==0, status==200, accepted==0, last_seq==299; rows raw==300 (дублей нет); accepted_sum raw==300; r[0].cur.acked==299; r[0].sent_total==300.
10. `i_epoch_change` — setup(300,0,0); c = icfg(100, 1); drive → rows raw==300; затем `af_ring_clear(&ST.ring[0])` (epoch 22; seq продолжается с 300) и добавь 30 записей: для i=0..29 `mk_raw(L_RAW[i], &rec); af_raw_encode(&rec, tmp); af_ring_push(&ST.ring[0], tmp)`; drive(max 50): rows raw==330; max_seq raw==329; r[0].cur.epoch==22; r[0].cur.acked==329; r[0].err==0.
11. `i_test_request` — setup(0,0,291); пробный запрос: `n = af_push_test_body(buf, sizeof buf)`, POST на "/ingest/env" заголовки Authorization Bearer G_TOKEN, X-AF-Device D1_MAC, X-AF-Epoch 0, X-AF-First-Seq 0, X-AF-Lost 0, X-AF-Ring env → status==200; af_push_parse_resp(resp) == 0, accepted==0, last_seq==-1; rows env==0 (в БД ничего не записано). Затем доставка env полностью (c = icfg(100, 4); drive) → rows env==291; повтор пробного запроса → status 200, accepted==0, last_seq==290; rows env остаётся 291.
