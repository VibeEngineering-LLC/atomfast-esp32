# Спека: web/push-model.js — чистая логика раздела «База данных» (отправка истории платы на приёмник)

Файл в стиле `web/store-clear.js` (UMD): первая строка
`(function (root, factory) { if (typeof module === 'object' && module.exports) { module.exports = factory(); } else { root.AFPUSH = factory(); } })(this, function () { 'use strict';`
последняя строка `return { ... };` и `});`. ES5 (`var`, `function`), без стрелок, без шаблонных строк, без DOM и без сети. Все тексты для пользователя — по-русски (UTF-8 прямо в строках). Вход `j` — ответ `GET /api/push`, любая часть может отсутствовать или быть неверного типа: функции не бросают исключений.

Экспорт (ровно эти имена): `validateForm`, `tokenHint`, `stateText`, `errText`, `statusView`, `ringRows`, `testText`, `apiErrText`, `resetConfirmText`, `RING_LABELS`.

## RING_LABELS
Объект `{ raw: 'сырые', agg: 'агрегаты', env: 'датчики среды' }`.

## validateForm(f, tokenSet)
`f` = `{enabled: bool, host: string, port: string, token: string, clearToken: bool}`; `tokenSet` — bool (токен уже сохранён на плате).
Возвращает `{ok: false, error: <текст>, field: <id поля>}` или `{ok: true, body: {...}}`. Порядок проверок и тексты (первая сработавшая):
1. `host` = trim. Если `host.length > 63` -> error `Адрес приёмника слишком длинный (не более 63 символов)`, field `pushHost`.
2. Если `host` непуст и не проходит правило адреса (ниже) -> `Недопустимый адрес приёмника: допустимы IPv4-адрес или имя из латинских букв, цифр, точек и дефисов`, field `pushHost`.
3. Если `enabled` и `host` пуст -> `Укажите адрес приёмника`, field `pushHost`.
4. Порт: `port` = trim; если не `/^\d+$/` -> `Порт должен быть целым числом от 1 до 65535`, field `pushPort`; число `p = parseInt(port,10)`; если `p < 1` или `p > 65535` -> `Порт должен быть от 1 до 65535`, field `pushPort`. (Порт проверяется всегда, даже при выключенной отправке.)
5. Токен (поле не обрезать пробелами): если `token.length > 64` -> `Токен слишком длинный (не более 64 символов)`; если есть символ с кодом < 0x21 или > 0x7E, либо `"` либо `\` -> `В токене допустимы только видимые символы ASCII без кавычек и обратной косой черты`; field `pushToken`.
6. Если `token` непуст и `clearToken` -> `Нельзя одновременно ввести токен и очистить сохранённый`, field `pushTokenClear`.
7. Если `enabled` и `clearToken` и токен пуст -> `Нельзя включить отправку и очистить токен`, field `pushTokenClear`.
8. Если `enabled` и токен пуст и не `tokenSet` -> `Укажите токен приёмника`, field `pushToken`.
Тело при успехе: `{enabled: <bool>, host: <host>, port: <число p>}`; плюс `token: <как введён>` ТОЛЬКО если токен непуст; плюс `clear_token: true` ТОЛЬКО если `clearToken` и токен пуст. Других ключей нет.
Правило адреса (копия `af_push_host_ok`): длина 1..63; первый и последний символ — латинская буква или цифра; все символы — латинские буквы, цифры, `.` или `-`; нет двух точек подряд; если адрес состоит только из цифр и точек — он обязан быть корректным IPv4 (ровно 4 части, каждая 1..3 цифры, значение 0..255).

## tokenHint(j)
Если `j.token_set === true` -> `токен задан (оставьте поле пустым, чтобы не менять)`, иначе `токен не задан`.

## stateText(j)
Если `j.auth_stop === true` -> `остановлено: приёмник отклонил токен`. Иначе по `j.state`: `off` -> `отправка выключена`; `idle` -> `включена, ждёт новых записей`; `sending` -> `идёт отправка`; `error` -> `ошибка отправки`; иначе `нет данных`.

## errText(name)
Таблица: `''` -> `—`; `net` -> `нет связи с приёмником`; `server` -> `приёмник ответил ошибкой сервера`; `auth` -> `приёмник отклонил токен`; `bad_batch` -> `приёмник отклонил пачку данных`; `too_big` -> `пачка слишком велика для приёмника`; `proto` -> `непонятный ответ приёмника`; `http4xx` -> `приёмник ответил ошибкой запроса (4xx)`; `no_device` -> `у платы нет идентификатора прибора`; `no_store` -> `хранилище истории недоступно`; `oom` -> `не хватило памяти на плате`. Неизвестная строка -> `ошибка: ` + строка; не строка (или undefined) -> `—`.

## statusView(j)
Возвращает `{enabled, conn, sent, fail, lastErr}` — строки для карточки статуса. Если `j` не объект -> все `—`.
- `enabled`: `да`/`нет` по `j.enabled === true`.
- `conn`: если `j.enabled !== true` -> `—`; иначе если `j.state === 'error'` или `j.auth_stop === true` -> `нет`; иначе если хотя бы у одного кольца в `j.ring` (raw, agg, env) число `last_ok_ts > 0` -> `есть`; иначе `ещё не было отправок`.
- `sent`: сумма `sent_total` по трём кольцам (нечисла считать 0), строкой.
- `fail`: сумма `fail_total` так же.
- `lastErr`: `errText` для первого (в порядке raw, agg, env) кольца с непустым `last_err.text`; если такого нет — `—`.

## ringRows(j)
Массив из трёх объектов `{id, label, text}` в порядке raw, agg, env (label из RING_LABELS). Если кольцо отсутствует в `j.ring` -> text `нет данных`. Если `on === false` -> text `не отправляется`. Иначе text = `ждёт отправки ` + pending (число, нечисло как 0) + `; ` + (acked_seq число >= 0 ? `подтверждено до № ` + acked_seq : `ещё не отправляли`) + `; отправлено ` + sent_total + `, ошибок ` + fail_total.

## testText(t)
`t` = объект `test` из ответа. Не объект или `state === 'idle'` -> пустая строка. `running` -> `проверка идёт…`. `done`: если `t.err` непустая строка -> `Не удалось: ` + errText(t.err) + (если число `http > 0`: ` (HTTP ` + http + `)`) + (если число `ms > 0`: `, ` + ms + ` мс`); иначе -> `Соединение работает: приёмник ответил` + (http > 0 ? ` (HTTP ` + http + `)` : ``) + ` за ` + ms + ` мс` + (`t.legacy === true` ? `; приёмник старой версии` : ``). Иное состояние -> пустая строка.

## apiErrText(status, err)
`status` — HTTP-код, `err` — строка из JSON `{ok:false, err:...}` (может быть пустой). Таблица (первое совпадение):
- status 401 -> `нужна авторизация`
- status 403 -> `отказ: недействительный токен страницы, обновите страницу`
- err `incomplete` -> `не заданы адрес приёмника и токен: сначала сохраните настройки с адресом и токеном`
- err `busy` -> `проверка уже идёт, подождите`
- err `not_ready` -> `отправка ещё запускается, повторите через несколько секунд`
- err `confirm_required` -> `нужно подтверждение`
- err `bad_value` -> `плата отклонила значения (проверьте адрес, порт и токен)`
- err `unknown_key`, `bad_body`, `json` -> `плата не поняла запрос (обновите страницу)`
- status 0 или не число -> `нет связи с платой`
- иначе -> `плата отклонила запрос (` + status + `)`.

## resetConfirmText(j)
Сумма `pending` по кольцам, у которых `on !== false` (нечисла как 0) = `n`. Возвращает: `Позиция отправки будет сброшена. Сейчас ждёт отправки ` + n + ` ` + plural(n) + `; после сброса отправка начнётся с самой старой записи, которая есть на плате. Данные на плате не удаляются, приёмник может получить часть записей повторно.` Где `plural(n)`: `запись` для n%10==1 и n%100!=11; `записи` для n%10 в 2..4 и n%100 не в 12..14 (то есть не в 10..19); иначе `записей`.
