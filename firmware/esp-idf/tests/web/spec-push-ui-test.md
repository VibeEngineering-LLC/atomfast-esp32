# Спека теста: tests/web/push-ui.test.js (DOM-обвязка раздела «База данных» на поддельном DOM)

Node-скрипт без фреймворка в стиле `tests/web/store-clear.test.js`: `check(name, fn)` для АСИНХРОННЫХ проверок — `async function check(name, fn)` с `await fn()`, печатает `ok  <имя>` или `FAIL <имя>: <сообщение>`; проверки выполняются последовательно (`await`), в конце `console.log('TESTS: ' + passed + '/' + total)` и `process.exit(passed === total ? 0 : 1)`. Модуль под тестом: файл `process.env.PUSHUI_MODULE || path.join(__dirname,'..','..','web','push-ui.js')`; модель: `require('../../web/push-model.js')` (или `process.env.HC_MODULE` не использовать).

## Поддельный DOM (функция `makeEnv(opts)`, возвращает `env`)
- Элемент: объект `{id, value:'', checked:false, hidden:false, disabled:false, textContent:'', className:'', _h:{}, addEventListener(t,f){(this._h[t]=this._h[t]||[]).push(f)}, focus(){env.document.activeElement=this}, click(){ (this._h.click||[]).forEach(f=>f({})) }}`.
- Идентификаторы элементов (создать все): `p_en p_state p_conn p_sent p_fail p_err p_ring_raw p_ring_agg p_ring_env pushNote pushWarn pushEnabled pushHost pushPort pushToken pushTokenHint pushTokenClear btnPushSave btnPushTest btnPushReset pushBackdrop pushDlg pushDlgTitle pushDlgText pushDlgCancel pushDlgOk pushResult pushTestResult sec-db`. Начальное `hidden`: `true` у `pushBackdrop`, `pushDlg`, `pushWarn`; у остальных `false`.
- `env.document = { activeElement: null, visibilityState: 'visible', getElementById(id){ return env.els[id] || null }, addEventListener(t,f){ env.docH[t]=(env.docH[t]||[]); env.docH[t].push(f) } }`.
- `env.calls` — массив вызовов сети: `{m:'GET'|'POST', url, body}`.
- `fetchJSON(url)`: записывает `{m:'GET',url}`; для `/api/push` возвращает очередной ответ из `opts.getQueue` (массив; когда остался один — возвращать его же); иначе бросает ошибку.
- `postJSON(url, body)`: записывает `{m:'POST',url,body: JSON.parse(JSON.stringify(body))}`; возвращает `opts.post[url]` (объект `{ok,status,data}`) или `{ok:true,status:200,data:{ok:true}}`.
- Контекст `vm`: `vm.createContext({document: env.document, fetchJSON, postJSON, AFPUSH: model, setInterval: function(){return 0}, setTimeout: function(f){ f(); return 0 }, console})`; код `push-ui.js` выполняется `vm.runInContext(src, ctx)`; затем `ctx.initPush()` и `await tick()`, где `tick()` = несколько раз `await new Promise(r => setImmediate(r))` (не менее 10 раз).
- `env.ctx = ctx`.

Образцы боевого вида — те же `LIVE` и `WORKING`, что в `spec-push-model-test.md` (ответы `GET /api/push` платы «.131»; определить в начале файла так же, `WORKING` — с `enabled:true, host:'192.0.2.10', token_set:true, state:'idle'` и ring.raw из образца: `acked_seq:244614,pending:12,sent_total:156784,fail_total:2,last_ok_ts:1793351040,last_err:{code:2,text:'server'}`).
Пакет событий: `press(env, id)` = `env.els[id].click()` и затем `await tick()`.

## Проверки (имена дословно; каждая отвечает за ОДНО правило)
1. `форма: поля заполняются из ответа платы, токен в поле не подставляется` — `getQueue: [Object.assign({}, WORKING, {token: 'SECRET-TOKEN-xyz-0123456789'})]` (вредный ответ с лишним полем `token`); после `initPush`: `pushHost.value === '192.0.2.10'`, `pushPort.value === '8480'`, `pushEnabled.checked === true`, `pushToken.value === ''`, и НИ в одном элементе (`textContent`, `value`, `className`) нет подстроки `SECRET`.
2. `статус: карточка и подсказка токена по ответу платы` — `getQueue: [WORKING]`: `p_en.textContent === 'да'`, `p_conn.textContent === 'есть'`, `p_sent.textContent === '156784'`, `p_ring_raw.textContent` содержит `подтверждено до № 244614`, `pushTokenHint.textContent` содержит `токен задан`.
3. `предупреждение о нелокальном адресе показывается только при public_addr` — для `warn:{no_tls:true,public_addr:true}` `pushWarn.hidden === false`; для `WORKING` (public_addr false) `pushWarn.hidden === true`.
4. `сохранение: ошибочный порт не уходит на плату` — `getQueue:[LIVE]`; ввод `pushHost.value='192.0.2.10'`, `pushPort.value='abc'`, `pushToken.value='tok_AbC123-xyz'`, `pushEnabled.checked=true`; `press btnPushSave`; нет вызовов POST; `pushResult.className` содержит `bad`; `pushResult.textContent` содержит `Порт`.
5. `сохранение: тело запроса без токена, если поле пустое` — `getQueue:[WORKING]`, поля из ответа (после initPush), `press btnPushSave`: один POST на `/api/push`, тело (`deepStrictEqual`) `{enabled:true, host:'192.0.2.10', port:8480}`.
6. `сохранение: введённый токен уходит один раз и поле очищается` — `getQueue:[LIVE]`; `pushEnabled.checked=true; pushHost.value='192.0.2.10'; pushPort.value='8480'; pushToken.value='tok_AbC123-xyz'`; `press btnPushSave`: тело POST содержит `token === 'tok_AbC123-xyz'`; после — `pushToken.value === ''`, и нигде в элементах нет подстроки `tok_AbC123`; `pushResult.className` содержит `ok`.
7. `очистка токена: уходит clear_token, а не пустой token` — `getQueue:[WORKING]`; `pushTokenClear.checked=true`; `pushEnabled.checked=false`; `press btnPushSave`: тело содержит `clear_token === true` и нет ключа `token`.
8. `проверка без адреса: ответ платы incomplete показан по-русски` — `getQueue:[LIVE]`, `post['/api/push/test'] = {ok:false,status:409,data:{ok:false,err:'incomplete'}}`; `press btnPushTest`: `pushTestResult.textContent` содержит `не заданы адрес приёмника и токен`, `className` содержит `bad`; запросов `GET /api/push` после POST теста нет (не опрашивать при ошибке старта).
9. `проверка: ожидает результат и показывает его` — `getQueue` из трёх ответов: `WORKING`, `Object.assign({}, WORKING, {test:{state:'running',http:0,ms:0,accepted:-1,err:'',ts:0,legacy:false}})`, `Object.assign({}, WORKING, {test:{state:'done',http:200,ms:42,accepted:0,err:'',ts:1793351100,legacy:false}})`; `press btnPushTest` и `await tick()` достаточно раз (не менее 50 тиков); `pushTestResult.textContent` равно `Соединение работает: приёмник ответил (HTTP 200) за 42 мс`, `className` содержит `ok`.
10. `сброс: нажатие кнопки только открывает диалог и ничего не отправляет` — `getQueue:[WORKING]`; `press btnPushReset`: `pushDlg.hidden === false`, `pushBackdrop.hidden === false`, нет POST-вызовов, `pushDlgText.textContent` содержит `Данные на плате не удаляются`.
11. `сброс: подтверждение отправляет confirm:true на /api/push/reset` — после открытия `press pushDlgOk`: ровно один POST с url `/api/push/reset` и телом `{confirm:true}`; `pushDlg.hidden === true`; `pushResult.textContent` содержит `сброшена`.
12. `сброс: отмена закрывает диалог без отправки` — открыть, `press pushDlgCancel`: `pushDlg.hidden === true`, нет POST-вызовов.
13. `сброс: подтверждающее окно браузера не используется` — исходный текст `push-ui.js` (читать `fs.readFileSync`) не содержит подстрок `confirm(` и `alert(` вне комментариев (убрать строки, начинающиеся с `//` или `*`, проверку делать по остальным; допустимо слово `confirm:` в литерале объекта, поэтому искать именно `confirm(`).
