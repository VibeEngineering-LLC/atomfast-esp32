# Запись в PostgreSQL после полного сброса платы: исследование (0.1.0-e16j)

Исследование по замечаниям к 0.1.0-e16j (issue #1): почему после полного сброса платы новые строки не попадают в наполненную базу и как это исправить. Это рабочие материалы, а не отредактированная публикация: каждый файл записан как есть, со ссылками на код той ревизии, по которой он писался (ветка `e16j-ota-auth`, `0bb9001`, либо более поздний HEAD `a27d2aa`; ревизия указана в шапке файла). Номера строк между ревизиями расходятся, поэтому ссылки вида `main/<файл>:<строка>` сверяйте с ревизией из шапки конкретного файла.

## Причина

Номер поколения `gen` берётся из эпохи кольца в момент **отправки**, а не измерения (`main/af_pg.c`, функция формирования пакета; для HEAD строки 838–844, для `e16j-ota-auth` диапазон на несколько строк выше). После полного стирания флеша эпоха и `seq` начинаются заново, ключи `(hwid, ring, gen, seq)` совпадают со старыми, и вставка `ON CONFLICT DO NOTHING` (`main/pg_batch.c:424`) отбрасывает новые строки без ошибки.

## Как читать

- Начинать с `CONCEPT-customer-2026-11-14.md`, затем проект выбранного варианта и его проверки.
- Проекты — до реализации: ни один вариант ещё не запускался, числа помечены как расчёт или оценка.
- Проверки адверсариальные: каждая ищет, как нарушить заявленные свойства; находки P0/P1/P2 и что из них учтено — внутри отчётов. Утверждения проектов, которые проверки опровергли, в самих проектах могут остаться без оговорки: актуальное состояние — в проверке.
- В текстах встречаются пометки внутреннего рабочего процесса: номера правил вида `#SA-3`, `#RISK-1`, слова «владелец», «оператор», «бриф», «чужой материал», сокращения RA/RB, SH/SH2, CH1/CH2, C:NN. Для содержания они не нужны.
- Ссылки на файлы, которых нет в этой папке (ранние планы, разборы, локальные скрипты пересчёта, схема БД), относятся к рабочим материалам и сюда не включены.
