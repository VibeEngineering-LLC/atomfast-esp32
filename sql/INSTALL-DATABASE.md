# База данных PostgreSQL для AtomFast Gateway: пошаговая инструкция с нуля

Инструкция для человека, который ставит PostgreSQL впервые и работает без помощника ИИ. Прошивка платы: 0.1.0-e16k (для 0.1.0-e16j запросы платы к базе те же; шаги, которые относятся только к e16k, помечены). Подписи кнопок и полей взяты из веб-страницы платы, значения по умолчанию и диапазоны из кода прошивки. Исходный код прошивки в этом репозитории не опубликован. Описание самой структуры базы: [`atomfast_pg_schema.md`](atomfast_pg_schema.md), скрипт создания: [`atomfast_pg_schema.sql`](atomfast_pg_schema.sql).

## 1. Что получится и что нужно

**Что получится.** Плата сама, без промежуточных программ, подключается к вашему серверу PostgreSQL по сети и добавляет в базу строки: сырые измерения, агрегаты по окнам и данные датчиков среды. Если связь пропала, плата хранит данные у себя и после восстановления досылает то, что не ушло. Буфер платы конечный: при долгом отсутствии сервера самые старые записи вытесняются новыми и в базу не попадут. Повторная отправка той же пачки дублей не создаёт (ключ `(hwid, ring, gen, seq)`, `ON CONFLICT DO NOTHING`, см. `atomfast_pg_schema.md`), но есть исключение, описанное в пункте 5, «Что важно».

**Ограничения, о которых надо знать заранее.**

- Плата входит в базу только по паролю в схеме SCRAM-SHA-256. Шифрования канала (SSL/TLS) нет: пароль не передаётся открытым текстом, но сами данные идут по сети открыто. Используйте только доверенную домашнюю или служебную сеть, не выставляйте порт базы в интернет.
- Плата пишет на один сервер.
- Плата работает только с базой, где есть таблицы и функция из `atomfast_pg_schema.sql`. Пустая база не подойдёт.

**Что нужно.**

- Компьютер, мини-ПК, Raspberry Pi или сервер, который включён постоянно и стоит в той же сети, что и плата (тот же роутер).
- Плата с прошивкой 0.1.0-e16j или 0.1.0-e16k, подключённая к вашей Wi-Fi сети. Её веб-страница открывается по адресу, который показывает роутер, либо по имени `atomfast-gw.local` (доступность `.local` зависит от вашей системы).
- Права администратора на сервере (установка программ, брандмауэр).
- Файл `atomfast_pg_schema.sql` из этой папки репозитория, сохранённый на сервер. Если качаете со страницы GitHub, берите кнопкой «Raw» или «Download raw file», не копированием из окна браузера.
- Заранее решите три значения: имя базы (`<имя_базы>`), имя логина для платы (`<логин>`) и пароль (`<пароль>`). Плата принимает видимые знаки ASCII без пробелов: имя базы и имя логина до 31 знака, пароль до 63 знаков. Но сервер PostgreSQL сворачивает прописные буквы в имени без кавычек в строчные и не принимает в таком имени дефис или первую цифру. Поэтому **для имени базы и логина используйте только строчные латинские буквы, цифры и знак подчёркивания, первым знаком букву**, например из двух-трёх слов через `_`; не берите зарезервированные слова SQL. Пароль лучше собрать из букв и цифр, без кавычек и обратной косой черты. Имя базы по умолчанию на плате `af_test`; вы можете выбрать любое.

## 2. Шаг 1. Установить PostgreSQL

Скрипту схемы нужен PostgreSQL. Схема создавалась и проверялась на **PostgreSQL 17.9**. В заголовке скрипта указано «PostgreSQL 14 и новее» (из-за формы `date_trunc` с тремя аргументами); на версиях ниже 17 это **не проверялось**. На версии ниже 14 скрипт остановится с ошибкой `function date_trunc(unknown, timestamp with time zone, unknown) does not exist` (по документации PostgreSQL), и после отката в базе ничего не останется: поставьте более новую версию. Если сомневаетесь, ставьте 17.

Установив, проверьте две версии. Версия клиента `psql` (она может отличаться от версии сервера, если на компьютере стоит несколько установок):

```
psql --version
```

Версию **сервера** показывает запрос в `psql` (после входа по пункту 3.1): `SHOW server_version;`. Если она ниже 14, дальше не идите.

### Windows

1. Скачайте установщик со страницы https://www.postgresql.org/download/windows/ (кнопка «Download the installer», программа компании EDB).
2. Запустите, оставьте компоненты по умолчанию (сервер PostgreSQL, pgAdmin, Command Line Tools). Порт оставьте `5432`.
3. Когда установщик попросит пароль суперпользователя `postgres`, придумайте и запишите его. Это пароль администратора базы, не пароль платы.
4. После установки откройте «SQL Shell (psql)» из меню «Пуск». Он спросит сервер, базу, порт и пользователя: нажимайте Enter для значений по умолчанию, затем введите пароль `postgres`.
5. Чтобы запускать `psql` из любой папки, добавьте `C:\Program Files\PostgreSQL\<версия>\bin` в переменную среды `PATH` и откройте терминал заново. В PowerShell путь с пробелом вызывается так: `& "C:\Program Files\PostgreSQL\<версия>\bin\psql.exe" --version`.

(по документации PostgreSQL и установщика; на Windows автором не проверялось)

### Linux (Debian, Ubuntu, Raspberry Pi OS)

```
sudo apt update
sudo apt install postgresql postgresql-client
sudo systemctl status postgresql --no-pager
```

Raspberry Pi OS основан на Debian, поэтому команды те же. На Debian служба `postgresql` может показывать «active (exited)»: это нормально, сам сервер запущен отдельной службой кластера. Какая версия поставится, зависит от выпуска системы; проверьте её по разделу выше. Чтобы получить PostgreSQL 17 на более старой системе, используйте официальный репозиторий PostgreSQL (инструкция на https://www.postgresql.org/download/linux/debian/).

(по документации PostgreSQL; конкретные дистрибутивы не проверялись)

### Linux (Fedora, RHEL, Rocky, Alma)

```
sudo dnf install postgresql-server
sudo postgresql-setup --initdb
sudo systemctl enable --now postgresql
```

Версия, которую ставит `dnf` из стандартного репозитория, может быть ниже 14 (например, на RHEL и Rocky 8). Тогда подключите репозиторий PGDG по инструкции на https://www.postgresql.org/download/linux/redhat/: в нём имена пакетов и служб содержат номер версии (например, `postgresql17-server`, служба `postgresql-17`), а первичная настройка делается командой из той же инструкции, а не `postgresql-setup --initdb`.

(по документации дистрибутива; не проверялось)

### Docker

Запускайте контейнер только из официального образа `postgres` с Docker Hub и сверьте версию тега. Сначала решите, на каком адресе контейнер будет слушать: `<адрес_сервера>` это адрес компьютера в вашей локальной сети. Пример (по документации образа; не проверялось):

```
docker run -d --name atomfast-pg --restart unless-stopped -e POSTGRES_PASSWORD=<пароль_администратора> -p <адрес_сервера>:5432:5432 -v atomfast-pgdata:/var/lib/postgresql/data postgres:17
```

Что здесь важно:

- `-p <адрес_сервера>:5432:5432` публикует порт только на одном адресе. Запись без адреса (`-p 5432:5432`) открывает порт на всех интерфейсах компьютера, и Docker делает это в обход `ufw` и `firewalld`: правила из пункта 4.4 на контейнер **не действуют**. Если плата и сервер на одном компьютере или вы только пробуете, используйте `127.0.0.1` вместо `<адрес_сервера>` (тогда плата подключиться не сможет). Пароль администратора задайте стойкий.
- Образ по умолчанию принимает подключения со всех адресов и, по документации образа (не сверялось), содержит в `pg_hba.conf` правило `host all all all scram-sha-256`. Это правило нужно заменить строкой из пункта 4.2 (только подсеть платы). Посмотреть действующие правила: `docker exec atomfast-pg psql -U postgres -c "SELECT line_number, type, database, user_name, address, auth_method FROM pg_hba_file_rules;"`; файл лежит внутри тома, правится так же, как в пункте 4.2, после чего `docker exec atomfast-pg psql -U postgres -c "SELECT pg_reload_conf();"`.
- `--restart unless-stopped` возвращает контейнер после перезагрузки компьютера. Том `-v` обязателен: без него данные пропадут вместе с контейнером.
- Скрипт лежит на вашем компьютере, а не в контейнере. Чтобы применить его, скопируйте файл в контейнер и запустите его там (подходит для любой оболочки): `docker cp atomfast_pg_schema.sql atomfast-pg:/tmp/atomfast_pg_schema.sql`, затем `docker exec atomfast-pg psql -v ON_ERROR_STOP=1 -U postgres -d <имя_базы> -f /tmp/atomfast_pg_schema.sql` (вместо пункта 3.4). Остальные команды из `psql` выполняйте как `docker exec -it atomfast-pg psql -U postgres`.

Новичкам удобнее обычная установка без контейнера.

## 3. Шаг 2. Создать базу, применить скрипт, создать логин для платы

Все команды этого шага выполняются от имени администратора PostgreSQL (в примерах пользователь `postgres`) на самом сервере.

### 3.1. Войти в psql

Windows (в командной строке или PowerShell):

```
psql -U postgres -h localhost
```

Linux (у пользователя `postgres` в системе нет пароля, поэтому входите через `sudo`; не включайте метод `trust` в `pg_hba.conf` ради удобства):

```
sudo -u postgres psql
```

Должно появиться приглашение вида `postgres=#`. Выйти: `\q`.

На Linux **все** команды `psql`, `pg_dump`, `createdb` и `pg_restore` из этой инструкции запускайте с `sudo -u postgres` в начале и без `-U postgres -h localhost`. Файлы, которые читает или пишет `postgres`, кладите в каталог, доступный этому пользователю (например, `/tmp`): домашний каталог с правами 750 `postgres` прочитать не сможет.

### 3.2. Проверить способ хранения паролей

Плата умеет входить только по SCRAM-SHA-256, поэтому пароль логина обязан храниться в этом виде. В приглашении `psql`:

```sql
SHOW password_encryption;
```

Ожидается `scram-sha-256`. В PostgreSQL 14 и новее это значение по умолчанию (по документации; не проверялось). Если показано `md5`, исправьте: выполните `ALTER SYSTEM SET password_encryption = 'scram-sha-256';`, затем `SELECT pg_reload_conf();` и повторите `SHOW`. Пароли, заданные до этого, останутся в старом виде: задайте их заново (пункт 3.5). Значение, записанное командой `ALTER SYSTEM`, сильнее строки в `postgresql.conf`: если потом правите `postgresql.conf`, а `SHOW` показывает прежнее, причина в этом.

### 3.3. Создать пустую базу

```sql
CREATE DATABASE <имя_базы>;
```

Имя в этой команде должно быть записано строчными буквами (см. раздел 1). Владельцем станет администратор (`postgres`). Это нормально: плата не должна быть владельцем.

Выйдите из `psql` командой `\q`.

### 3.4. Применить скрипт

Перейдите в папку, где лежит `atomfast_pg_schema.sql`, и выполните (все команды в одну строку):

```
psql -v ON_ERROR_STOP=1 -U postgres -h localhost -d <имя_базы> -f atomfast_pg_schema.sql
```

Linux: `sudo -u postgres psql -v ON_ERROR_STOP=1 -d <имя_базы> -f /tmp/atomfast_pg_schema.sql` (сначала скопируйте файл в `/tmp`). Docker: см. раздел про Docker.

Windows: в скрипте русские комментарии в кодировке UTF-8, а консоль Windows может работать в другой. Перед запуском задайте кодировку клиента:

- командная строка: `set PGCLIENTENCODING=UTF8`
- PowerShell: `$env:PGCLIENTENCODING = "UTF8"`

(по документации PostgreSQL; не проверялось. Если этого не сделать, `psql` может остановиться с сообщением о неверной последовательности байт.)

Что должно получиться: команды `CREATE TABLE`, `CREATE FUNCTION`, `CREATE VIEW`, `GRANT` и в конце `COMMIT`, без строк `ERROR`. Параметр `ON_ERROR_STOP=1` останавливает выполнение на первой ошибке, а скрипт выполняется одной транзакцией (`BEGIN`…`COMMIT`), поэтому после ошибки в базе не останется половины схемы. Ошибка про `date_trunc` означает версию сервера ниже 14 (раздел 2).

Проверка: войдите в базу и посмотрите таблицы.

```
psql -U postgres -h localhost -d <имя_базы> -c "\dt"
```

В списке должны быть `hardware`, `af_raw`, `af_agg`, `af_env`, `af_cursor`, `af_gap`, `af_import_log` (7 таблиц, по `CREATE TABLE` в скрипте).

Скрипт также создаёт две группы-роли без права входа и без пароля: `af_writer` (запись) и `af_reader` (чтение). Для создания групп нужно право `CREATEROLE`; у `postgres` оно есть. Если вы запускаете скрипт под другим пользователем и получили ошибку о нехватке прав на создание роли, смотрите пункт 3.6.

### 3.5. Создать логин для платы и выдать ему право записи

Зайдите в `psql` под администратором (пункт 3.1) и выполните:

```sql
CREATE ROLE <логин> LOGIN;
\password <логин>
GRANT af_writer TO <логин>;
```

Команда `\password` попросит ввести пароль дважды, не показывая его, и сохранит его в защищённом виде; так пароль не попадает в историю команд. Введите `<пароль>`, выбранный в разделе 1.

Проверка (из `psql`, под администратором):

```sql
SELECT rolname, rolcanlogin, left(rolpassword, 14) AS pw_kind FROM pg_authid WHERE rolname = '<логин>';
SELECT pg_has_role('<логин>', 'af_writer', 'member');
```

Ожидается `rolcanlogin = t`, `pw_kind = SCRAM-SHA-256$` и `t` во втором запросе (по документации PostgreSQL; сами запросы автором не выполнялись).

Права группы `af_writer` по скрипту: чтение и вставка в `hardware`, `af_raw`, `af_agg`, `af_env`, `af_gap`, `af_import_log`; чтение, вставка и обновление в `af_cursor`; право временных таблиц на базу. Этого хватает плате. Удалять данные и менять результаты измерений эта роль не может.

### 3.6. Если нет права CREATEROLE

Это бывает, когда база выделена вам хостингом или администратор не выдал вам роль с `CREATEROLE`. Право `CREATEROLE` нужно и для создания самого логина (`CREATE ROLE ... LOGIN`, пункт 3.5): если его нет, логин создайте в панели хостинга или попросите администратора. Остальное:

1. Откройте `atomfast_pg_schema.sql` в текстовом редакторе, который сохраняет файл в UTF-8 (не в старом Блокноте Windows), и удалите (или закомментируйте) раздел «7. Роли» в конце файла: от строки `-- 7. Роли` до строки перед `COMMIT;` включая все `GRANT` и `REVOKE`.
2. Примените скрипт, как в пункте 3.4.
3. Дайте логину платы права напрямую, тот же набор, что у группы `af_writer`:

```sql
GRANT SELECT, INSERT ON hardware, af_raw, af_agg, af_env, af_gap, af_import_log TO <логин>;
GRANT SELECT, INSERT, UPDATE ON af_cursor TO <логин>;
GRANT TEMPORARY ON DATABASE <имя_базы> TO <логин>;
```

Плата сама пользуется таблицами `hardware`, `af_raw`, `af_agg`, `af_env` и функцией `af_hwid`; остальные права даны «как у группы», чтобы набор совпадал с проверенным вариантом. Право `TEMPORARY` у обычных ролей по умолчанию есть, но на хостинге его могли отозвать.

(по документации PostgreSQL; вариант без `CREATEROLE` автором не проверялся)

## 4. Шаг 3. Разрешить плате подключаться

По умолчанию PostgreSQL принимает подключения только с самого сервера. Нужно две настройки и открытый порт. Параметры меняются в двух файлах; их расположение показывают запросы (выполните в `psql` под администратором):

```sql
SHOW config_file;
SHOW hba_file;
```

Обычные места (для ориентира; доверяйте ответу запроса): Debian и Ubuntu `/etc/postgresql/<версия>/main/`, Windows `C:\Program Files\PostgreSQL\<версия>\data\`, Fedora и RHEL `/var/lib/pgsql/data/` (или `/var/lib/pgsql/<версия>/data/`). Править файлы нужно от администратора системы.

### 4.1. listen_addresses

В `postgresql.conf` найдите строку `listen_addresses` (обычно закомментирована и равна `'localhost'`) и поставьте один из вариантов:

```
listen_addresses = 'localhost,<адрес_сервера>'
```

Так сервер слушает локальный адрес и один адрес в вашей сети; команды `psql -h localhost` из этой инструкции продолжают работать. Если нужно проще, `listen_addresses = '*'` (все интерфейсы). Не ставьте один `<адрес_сервера>` без `localhost`: тогда `psql -h localhost` перестанет подключаться. Если адрес сервера выдаёт роутер, закрепите его за сервером постоянно, иначе после смены адреса сервер перестанет слушать нужный. Строка `password_encryption = 'scram-sha-256'` в том же файле допустима, если пункт 3.2 показал другое, но значение, сохранённое через `ALTER SYSTEM`, её перекроет (см. пункт 3.2).

### 4.2. pg_hba.conf

В `pg_hba.conf` добавьте строку **выше** общих правил (PostgreSQL читает правила сверху вниз и берёт первое подходящее):

```
host    <имя_базы>    <логин>    <подсеть>/<маска>    scram-sha-256
```

Что такое `<подсеть>/<маска>`: адрес сети и длина маски в битах. Для типичной домашней сети с маской 255.255.255.0: если адрес сервера `A.B.C.D`, пишется `A.B.C.0/24`. Для маски 255.255.0.0 длина 16 (`A.B.0.0/16`), для 255.255.255.128 длина 25, и так далее: длина равна числу единичных бит в маске. Допустимо вместо подсети указать точный адрес платы с маской `/32`, но адрес платы может измениться (закрепите за ней постоянный адрес в роутере).

Важно: строка должна начинаться со слова `host`, а не `hostssl`, потому что плата не использует шифрование канала (`atomfast_pg_schema.md`, раздел «Как подключается плата»). Метод `scram-sha-256`, не `md5` и не `trust`.

### 4.3. Применить настройки

`listen_addresses` вступает в силу только после **перезапуска** сервера; `pg_hba.conf` достаточно перечитать.

- Linux: `sudo systemctl restart postgresql` (в системах с версией в имени службы: `postgresql-<версия>`).
- Windows: откройте «Службы», найдите службу `postgresql-x64-<версия>`, команда «Перезапустить».
- Только `pg_hba.conf`: в `psql` выполните `SELECT pg_reload_conf();`.

Проверка (из `psql`): `SHOW listen_addresses;` показывает новое значение, `SELECT * FROM pg_hba_file_rules;` показывает вашу строку без значения в столбце `error` (по документации PostgreSQL).

### 4.4. Порт 5432 и брандмауэр

Порт PostgreSQL по умолчанию 5432. Если сервер защищён брандмауэром, откройте порт только для вашей подсети.

Windows (PowerShell от администратора, по документации Windows, не проверялось):

```
New-NetFirewallRule -DisplayName "PostgreSQL 5432" -Direction Inbound -Protocol TCP -LocalPort 5432 -RemoteAddress <подсеть>/<маска> -Action Allow
```

Linux с `ufw`: `sudo ufw allow from <подсеть>/<маска> to any port 5432 proto tcp`. С `firewalld`: `sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="<подсеть>/<маска>" port port="5432" protocol="tcp" accept'`, затем `sudo firewall-cmd --reload` (по документации; не проверялось). Для контейнера Docker эти правила не действуют (см. раздел про Docker).

**Предупреждение.** Данные идут между платой и сервером без шифрования: любой, кто подключён к той же сети, может их увидеть. Используйте только доверенную сеть, не пробрасывайте порт 5432 с роутера в интернет и не открывайте его для всех адресов.

## 5. Шаг 4. Настроить плату

1. Откройте веб-страницу платы в браузере (по IP-адресу платы или `http://atomfast-gw.local/`). Страница настроек открывается по адресу `/system`; в меню разделов найдите нужные пункты.
2. **Только для e16k.** Если запись нужного вида ещё не включена, откройте раздел **«Хранилище»**, группа **«Что записывать»**, и включите **«Сырые»**, **«Агрегаты»**, **«Датчики среды»** по необходимости. Если вид не записывается в память платы, отправить его в базу нельзя: в блоке «Что отправлять» (пункт 5 ниже) его флажок недоступен, под флажками подпись «запись выключена в разделе Хранилище». В e16j такой зависимости в описании выпуска нет.
3. Откройте раздел **«База данных»** (на странице есть карточка «Отправка истории в базу» с токеном и пометкой про HTTP-приёмник: она для другого способа и для прямой записи в PostgreSQL не нужна; ниже неё находятся карточки **«PostgreSQL: состояние»** и **«PostgreSQL: настройки»**; работайте с ними).
4. В карточке **«PostgreSQL: настройки»** заполните поля. Что означает каждое:

| Поле на странице | Что вписать | По умолчанию | Допустимо |
|---|---|---|---|
| **Режим** | выберите «Прямое подключение к PostgreSQL» (варианты: «Выключено», «Через HTTP-приёмник (резерв, плата не использует)», «Прямое подключение к PostgreSQL») | «Выключено» | только три варианта списка |
| **Адрес сервера** | IP-адрес или имя сервера (`<адрес_сервера>`) | пусто | латинские буквы, цифры, точки, дефисы, до 63 знаков; первый и последний знак буква или цифра; без двух точек подряд; если запись состоит только из цифр и точек, она должна быть корректным адресом IPv4 (например, `300` в любом разряде недопустимо) |
| **Порт (1-65535)** | порт PostgreSQL | 5432 | 1-65535 |
| **База данных** | `<имя_базы>` | `af_test` | до 31 видимого ASCII-знака без пробелов |
| **Пользователь** | `<логин>` | пусто | до 31 видимого ASCII-знака без пробелов |
| **Пароль** | `<пароль>` | пусто | до 63 видимых ASCII-знаков без пробелов |

Страница проверяет адрес мягче платы: она может принять значение, которое плата потом отвергнет сообщением `?: host` (раздел 7). Следите за правилами из таблицы.

Пароль хранится только на плате и на странице не показывается. Рядом с полем подпись «пароль задан (оставьте поле пустым, чтобы не менять)» или «пароль не задан». Флажок **«Очистить сохранённый пароль»** стирает пароль на плате. **Если вы меняете адрес сервера или порт, плата стирает сохранённый пароль, если вы не ввели новый в том же сохранении.** Страница при этом всё равно пишет «сохранено», а подпись «пароль задан» может устареть до обновления страницы; затем «Проверить соединение» ответит «не заданы адрес сервера, пользователь и пароль». Поэтому при смене адреса или порта всегда вводите пароль заново. Адрес в виде IP надёжнее имени: плата ищет имя через DNS, и имя вида `.local` может не находиться.

В выпадающем блоке **«Дополнительно»** остальные параметры; обычно их менять не нужно:

| Поле | Смысл | По умолчанию | Допустимо |
|---|---|---|---|
| **Период отправки, с (10-3600)** | как часто плата отправляет накопленное | 60 | 10-3600 |
| **Записей в пачке (10-1000)** | сколько записей в одной команде вставки | 200 | 10-1000 |
| **Размер пачки, байт (4096-32768)** | предел размера одной пачки | 32768 | 4096-32768 |
| **Таймаут, с (2-30)** | сколько ждать ответа сервера | 8 | 2-30 |
| **Предел итераций SCRAM (4096-1000000)** | максимум итераций проверки пароля, которое плата согласна выполнить | 100000 | 4096-1000000 |

5. Блок **«Что отправлять»**: флажки **«Сырые»**, **«Агрегаты»**, **«Датчики среды»**. По умолчанию включены все три, но фактически уходят только те, чья запись включена в «Хранилище» (e16k). Если запись вида выключена, флажок недоступен. Если выключить все три, режим «Прямое подключение» сохранить не удастся: сообщение «Выберите, что отправлять».
6. Нажмите **«Сохранить»**. Ожидается надпись «сохранено». Если плата не принимает значение, под кнопками появится причина (например, «Укажите пароль», «Укажите адрес сервера», «Укажите пользователя»).
7. Нажмите **«Проверить соединение»**. Плата входит на сервер под вашим логином и паролем и выполняет запрос `SELECT 1`. Хорошо: «Соединение работает: вход выполнен за N мс, из них SCRAM M мс». Плохо: «Не удалось: …» с причиной (раздел 7). Обратите внимание: проверка **не проверяет таблицы и права на запись**; их выявит первая реальная отправка. **Обе кнопки, «Проверить соединение» и «Отправить сейчас», действуют только когда на плате выбран прибор** (раздел «BLE», карточка «Выбор прибора»): без прибора проверка закончится сообщением «сервер не ответил за N с» (N равно таймауту, умноженному на 3, плюс 5), хотя причина не в сервере.
8. Нажмите **«Отправить сейчас»**: плата не ждёт период и отправляет сразу. Ожидается «отправка запущена». В режиме «Выключено» кнопка отвечает «отправка выключена: выберите режим «Прямое подключение» и сохраните настройки»; в режиме «Через HTTP-приёмник» отвечает «клиент базы ещё запускается, повторите через несколько секунд», хотя ждать бесполезно: выберите «Прямое подключение». То же сообщение «клиент базы ещё запускается…» бывает и у «Проверить соединение», если вы не нажали «Сохранить» после выбора режима.

Что важно:

- Если вы меняете адрес, порт, базу или пользователя, плата сбрасывает свои позиции отправки и начинает слать накопленное с начала. В пределах одной загрузки платы дублей в базе не будет (ключ и `ON CONFLICT DO NOTHING`). Если между первой отправкой и этим повтором плата перезагружалась, повторно отправленные строки уходят под новым номером «поколения» (`gen`) и могут создать повторные строки. При обычной перезагрузке без сброса позиции плата продолжает с сохранённого места под новым `gen`, уже отправленное заново не уходит: на стенде после плановых перезагрузок пересечений между поколениями не было. При внезапной потере питания сохранённая позиция может отставать примерно на 30 секунд, и последние записи могут уйти повторно под новым `gen`; реальный обрыв питания на плате не проверялся. Такие случаи показывает представление `af_dup_suspects` (`SELECT * FROM af_dup_suspects;`).
- Пока плата не подключилась к дозиметру и в её памяти нет записей, отправлять нечего. Данные в базе появятся после того, как прибор выбран, подключён, и записи накопились.
- Если плата сообщает об ошибке пароля, она **останавливает отправку**, пока вы не нажмёте «Сохранить» (даже не меняя значений): это снимает остановку.

## 6. Шаг 5. Проверить, что данные пошли

### 6.1. По состоянию на плате

В карточке **«PostgreSQL: состояние»**:

- **Состояние**: «Выключено», «Ждёт очереди», «Соединение», «Авторизация», «Отправка», «Пауза после ошибки» или «Остановлено». Осторожно: надпись «Пауза после ошибки» плата показывает и в обычном ожидании следующего периода после удачного прохода, и во время паузы после ошибки. Поэтому судите по строке «Последняя ошибка» и по счётчикам, а не только по этой надписи. «Остановлено» означает, что отправка остановлена (например, отказ пароля) до нажатия «Сохранить»; такое состояние бывает и при остановке задачи отправки.
- **Режим**: «Прямое подключение».
- **Сервер**: адрес, который вы задали.
- **Вставлено строк**: растёт после каждой успешной отправки.
- **Пропущено (уже есть)**: строки, которые база уже имела (при повторной отправке).
- **Отброшено (неверные)**: строки, которые плата сама отбраковала при формировании пачки (не прошли её проверку значений). Нарушения ограничений на сервере сюда не входят: они останавливают кольцо (раздел 7).
- **Неудачных сессий** и **Успешных сессий**: счётчики.
- **Позиция: сырые / агрегаты / датчики среды**: номер записи, до которой всё подтверждено сервером.
- **Время SCRAM**: сколько заняла проверка пароля, мс.
- **Последняя ошибка**: «нет» или текст ошибки (раздел 7).

Признак успеха: «Успешных сессий» и «Вставлено строк» растут, «Последняя ошибка: нет».

### 6.2. По базе

Подключитесь к базе под администратором (Linux: `sudo -u postgres psql -d <имя_базы>`):

```
psql -U postgres -h localhost -d <имя_базы>
```

Сколько строк и приборов:

```sql
SELECT (SELECT count(*) FROM af_raw) AS raw_rows,
       (SELECT count(*) FROM af_agg) AS agg_rows,
       (SELECT count(*) FROM af_env) AS env_rows,
       (SELECT count(*) FROM hardware) AS devices;
```

Плата при первой отправке сама добавляет свой дозиметр в `hardware`; `devices` должно быть 1 (если у вас один прибор).

Последние 20 сырых измерений:

```sql
SELECT r.ts, r.doserate AS "мкЗв/ч", r.cps, r.dose AS "мЗв"
FROM af_raw r JOIN hardware h ON h.id = r.hwid
ORDER BY r.ts DESC, r.seq DESC
LIMIT 20;
```

Те же запросы с фильтром по MAC прибора, пропуски в нумерации, суточные средние и другие примеры: в `atomfast_pg_schema.md`, раздел «Примеры запросов».

Почасовые средние (готовые представления): `SELECT * FROM af_raw_hourly ORDER BY hour_utc DESC LIMIT 24;`

Время `ts` хранится в UTC (`timestamptz`); чтобы увидеть местное, выполните `SET TIME ZONE '<часовой_пояс>';` в `psql` (например, значение из списка `pg_timezone_names`).

## 7. Если запись не идёт: сообщения и что делать

Сообщение в строке «Последняя ошибка» состоит из пятизначного кода SQLSTATE и текста, который прислал сервер: `<код>: <текст>`. Вся строка не длиннее 160 байт, текст сервера обрезается раньше (около 95 байт). Язык текста задаёт сервер. Если кода нет (ошибка возникла на плате или в сети), вместо него стоит `?`.

### 7.1. Как плата реагирует на коды

По коду плата решает, повторять ли отправку:

- **Повторяет** с нарастающей паузой 1, 5, 30 и далее до 120 с: классы `08` (соединение), `53` (нехватка ресурсов сервера), `58` (ошибка системы), `XX`, а также `57P01`, `57P02`, `57P03`, `40001`, `40P01`, `55P03`, и любой неизвестный код.
- **Останавливает отправку целиком до «Сохранить»**: класс `28` (пароль, роль, отказ в подключении).
- **Останавливает только одно кольцо** (сырые, агрегаты или среда) до «Сохранить»: классы `0A`, `21`, `22`, `23`, `25`, `26`, `2B`, `34`, `3D`, `3F`, `40` (кроме `40001`, `40P01`), `42`, `44`, `P0`, а также `50`-`57` кроме перечисленных выше.

### 7.2. Таблица: что видите, причина, что делать

Значения кодов SQLSTATE приведены по документации PostgreSQL (приложение «Коды ошибок»); что именно покажет ваш сервер, зависит от его версии и настроек. Плата выводит код и текст сервера как пришли.

| Что видите на плате | Причина | Что делать |
|---|---|---|
| `28P01: …` (пароль не подошёл), «неверное имя пользователя или пароль» | Неверный пароль или имя логина; либо пароль в базе хранится не как SCRAM | Проверьте логин и пароль; задайте пароль заново через `\password <логин>` при `password_encryption = scram-sha-256`; на плате введите пароль и нажмите «Сохранить». Имя базы или логина с прописными буквами сервер сворачивает в строчные: см. раздел 1 |
| `28000: …` (часто в тексте «no pg_hba.conf entry») | В `pg_hba.conf` нет подходящей строки для адреса платы, базы или логина; либо роль не может входить | Шаг 3, пункт 4.2: подсеть, имя базы, логин, `host` и `scram-sha-256`; затем `SELECT pg_reload_conf();` и «Сохранить» на плате |
| `3D000: …` (база не существует) | Имя базы на плате не совпадает с созданным | Поправьте поле «База данных» на плате или создайте базу (шаг 2); при входе плата повторяет попытки с нарастающей паузой, не останавливаясь (выведено из кода платы; на живой плате не наблюдалось) |
| `42P01: …` (таблица не существует) | Не применён скрипт, применён в другой базе или в другой схеме | Шаг 2, пункт 3.4; убедитесь, что таблицы лежат в схеме по умолчанию (`public`) |
| `42501: …` (нет прав) | Логину не выданы права на таблицы | `GRANT af_writer TO <логин>;` (пункт 3.5); затем «Сохранить» на плате |
| `23514: …` (нарушено ограничение) | Строка не проходит `CHECK` схемы (значение вне допустимого диапазона) | Не правьте таблицы; пришлите сообщение и строку в репозиторий (раздел Issues). Кольцо остановится до «Сохранить» |
| `22…` или `23…`, другие коды в списке п. 7.1 | Ошибка данных или ограничения | Прочитайте текст сервера; кольцо остановлено до «Сохранить» |
| `?: hwid` / «не удалось определить код устройства» | Плата не получила номер прибора: нет функции `af_hwid` (скрипт не применён), нет права на `hardware`, либо сервер вернул ошибку на этот запрос | Примените скрипт (пункт 3.4); проверьте `GRANT` (пункт 3.5). Права можно проверить без записи в таблицу, под администратором: `SELECT has_function_privilege('<логин>', 'af_hwid(macaddr)', 'EXECUTE'), has_table_privilege('<логин>', 'hardware', 'INSERT');` (по документации PostgreSQL). Не вызывайте `af_hwid` вручную с выдуманным MAC: функция добавляет строку в `hardware`, и счёт приборов в пункте 6.2 перестанет сходиться |
| `?: connect` (сетевая ошибка) | Сервер недоступен: выключен, неверный адрес или порт, брандмауэр, другая сеть | Проверьте адрес и порт на плате, включён ли сервер, раздел 4.4; `Test-NetConnection <адрес_сервера> -Port 5432` в PowerShell или `nc -vz <адрес_сервера> 5432` в Linux (по документации; не проверялось) |
| `?: dns` / «адрес сервера не найден» | Имя не находится | Укажите IP-адрес вместо имени |
| `?: host` | Адрес в поле «Адрес сервера» недопустим для платы | Правила в таблице пункта 5: латинские буквы, цифры, точки, дефисы; первый и последний знак буква или цифра; без двух точек подряд; запись из одних цифр и точек должна быть корректным IPv4 |
| `?: startup` или `?: ready` | Соединение установлено, но сервер ответил не так, как ожидается, или закрыл связь | Проверьте журнал сервера; убедитесь, что порт принадлежит PostgreSQL |
| `auth_unsup` / «сервер требует неподдерживаемую проверку пароля (нужен SCRAM-SHA-256)» | Сервер запросил не SCRAM: для вашего адреса в `pg_hba.conf` указан метод `password` или `trust`, либо пароль роли сохранён как `md5` | Поставьте `scram-sha-256` в строке, подходящей плате (пункт 4.2); пароль в базе должен быть SCRAM (пункт 3.2) |
| `scram_iter` / «сервер просит слишком много итераций SCRAM (поднимите предел…)» | Число итераций хранения пароля на сервере больше предела на плате (100000 по умолчанию) | Уменьшите число итераций на сервере (параметр `scram_iterations` в PostgreSQL 16 и новее, по документации) и задайте пароль заново; либо поднимите «Предел итераций SCRAM» в «Дополнительно» до 1000000 |
| `?: no wifi` | У платы нет Wi-Fi | Проверьте сеть платы |
| `?: ota busy` | Идёт установка прошивки | Дождитесь окончания |
| `?: rows mismatch` | Сервер сообщил, что вставил больше строк, чем отправлено | Сообщите об ошибке в репозиторий с версией прошивки |
| `?: csv_fill`, `?: wire_query`, `?: insert_rows parse`, `?: send`, `?: recv`, `?: recv Z`, `?: alloc` | Внутренняя ошибка платы (формат данных, связь, нехватка памяти) | Нажмите «Сохранить» (сбросит остановку); при повторе сообщите в репозиторий |
| `function date_trunc(...) does not exist` при применении скрипта | Версия сервера ниже 14 | Поставьте PostgreSQL 14 или новее (лучше 17); раздел 2 |

Сообщения под кнопками на странице:

| Сообщение | Что значит |
|---|---|
| «нужна авторизация» | страница потеряла доступ к плате; обновите страницу |
| «отказ: недействительный токен страницы, обновите страницу» | обновите страницу (F5) |
| «не заданы адрес сервера, пользователь и пароль: сначала сохраните настройки» | заполните поля и нажмите «Сохранить»; после смены адреса или порта пароль нужно ввести заново |
| «проверка уже идёт, подождите» | дождитесь результата |
| «клиент базы ещё запускается, повторите через несколько секунд» | повторите через несколько секунд; если не проходит, проверьте, что выбран режим «Прямое подключение» и нажато «Сохранить» |
| «плата отклонила значения (проверьте поля формы)» | значение вне допустимого диапазона |
| «нельзя включить отправку: запись этого вида выключена в разделе Хранилище» | редкое сообщение (e16k): обычно флажок просто недоступен; включите запись в «Хранилище» (шаг 4, пункт 2) |
| «сервер не ответил за N с» | сервер не ответил за время проверки, либо на плате не выбран прибор (пункт 5.7); смотрите раздел 4 и таймаут |

После исправления причины на сервере или на плате **нажмите «Сохранить»** (значения можно не менять): это снимает остановку и очищает ошибки, плата возобновляет отправку. Затем «Отправить сейчас».

Полезные запросы на стороне сервера для диагностики (по документации PostgreSQL):

```sql
SELECT * FROM pg_hba_file_rules WHERE error IS NOT NULL;
SELECT pid, usename, client_addr, state, backend_start FROM pg_stat_activity WHERE datname = '<имя_базы>';
```

А также журнал сервера: Debian и Ubuntu `/var/log/postgresql/postgresql-<версия>-main.log`, Windows `data\log\` в каталоге установки. Отказы входа записываются там с причиной.

## 8. Обслуживание

### 8.1. Резервная копия

Создать копию (под администратором, по документации PostgreSQL; не проверялось). Linux: `sudo -u postgres pg_dump -d <имя_базы> -Fc -f /tmp/<имя_файла>.dump`. Windows:

```
pg_dump -U postgres -h localhost -d <имя_базы> -Fc -f <имя_файла>.dump
```

`pg_dump` сохраняет данные и объекты одной базы, но **не сохраняет роли** (`af_writer`, `af_reader`, логин платы и его пароль): роли хранятся на уровне всего сервера. Поэтому на **новом сервере** перед восстановлением создайте роли заново: `CREATE ROLE af_writer NOLOGIN; CREATE ROLE af_reader NOLOGIN;`, затем после восстановления создайте логин и выдайте ему членство по пункту 3.5. Либо сохраните роли отдельно: `pg_dumpall --globals-only -f roles.sql` (файл содержит хеши паролей, храните его как секрет). Восстановить в **новую пустую** базу:

```
createdb -U postgres -h localhost <новая_база>
pg_restore -U postgres -h localhost -d <новая_база> <имя_файла>.dump
```

(Linux: те же команды с `sudo -u postgres` и без `-U postgres -h localhost`.) Хранить копию нужно на другом диске или другом компьютере. Делайте копию по расписанию (cron в Linux, «Планировщик заданий» в Windows) и периодически проверяйте, что она восстанавливается.

### 8.2. Очистка старых данных

Данные автоматически не удаляются: база растёт. Функция `af_purge` (описана в скрипте) удаляет старые строки: сырые старше заданного числа суток и, если указано второе число, агрегаты старше него. **Удаление необратимо.** Сначала сделайте копию (пункт 8.1) и посмотрите, сколько строк будет удалено:

```sql
SELECT count(*) FROM af_raw WHERE ts < now() - interval '365 days';
```

Затем выполните удаление в явной транзакции, чтобы иметь возможность отменить (пример: сырые старше 365 суток, агрегаты не трогаются):

```sql
BEGIN;
SELECT * FROM af_purge(365);
```

Если результат устраивает, выполните `COMMIT;`, иначе `ROLLBACK;`. С агрегатами: `SELECT * FROM af_purge(365, 1825);`. Функция возвращает число удалённых строк. Запускать её должен администратор: у роли платы нет права удалять. Осторожно: если вы позже на плате смените адрес, базу или пользователя, плата пошлёт накопленное с начала, и удалённое, ещё лежащее в её памяти, вернётся в базу.

### 8.3. Применить скрипт заново и обновить схему

Скрипт можно запускать повторно командой из пункта 3.4: объекты создаются с `IF NOT EXISTS` и `OR REPLACE`, данные в таблицах **не удаляются**. Два уточнения: при повторном запуске скрипт пересоздаёт ограничения таблицы `af_env` (удаляет и добавляет заново; в скрипте блок с `DROP CONSTRAINT` и `ADD CONSTRAINT`), на большой таблице это занимает время и при строках, нарушающих новые правила, закончится ошибкой, а права ролей `af_writer` и `af_reader` задаются заново целиком (раздел «7. Роли» скрипта); если вы выдали им что-то лишнее вручную, это пропадёт. Перед обновлением схемы на рабочей базе сделайте копию (пункт 8.1).

### 8.4. Сменить пароль логина платы

В `psql` под администратором: `\password <логин>`; затем на плате введите новый пароль в поле «Пароль» и нажмите «Сохранить».

### 8.5. Удалить всё и начать заново

**Необратимо: все данные базы пропадут.** Только если база нужна пустой и копия сделана. Порядок:

1. На плате выберите режим «Выключено» и нажмите «Сохранить»: пока плата подключена, `DROP DATABASE` не выполнится («being accessed by other users»).
2. `DROP DATABASE <имя_базы>;` (из другой базы, например `postgres`), затем пункты 3.3-3.4. Логин платы и группы `af_writer`, `af_reader` останутся (они принадлежат серверу, не базе); снова включить логину `GRANT af_writer` не нужно, если вы не удаляли роли.
3. Верните на плате режим «Прямое подключение» и нажмите «Сохранить».

Важно про позиции платы: плата помнит, до какой записи всё подтверждено, и сбрасывает эту позицию только при смене адреса, порта, базы или пользователя. Если вы пересоздали базу с тем же именем и теми же настройками, плата продолжит с прежней позиции: то, что она уже отправила до удаления, в новую базу не вернётся (восстановите это из копии). Чтобы плата послала накопленное заново, измените на плате любое из четырёх значений и верните обратно, нажимая «Сохранить» (при смене адреса или порта введите пароль заново). Это выведено из кода платы, на плате не проверялось; о повторных строках после перезагрузки платы см. пункт 5, «Что важно».

## 9. Что проверено, а что нет

**Проверено автором документа на уровне чтения кода и страницы.** Названия полей, кнопок, разделов, значения по умолчанию, диапазоны, тексты сообщений и список ошибок сверены с исходниками прошивки и веб-страниц платы. Исходный код прошивки в репозитории не опубликован, поэтому ссылок на его строки здесь нет; о расхождении сообщите в Issues.

**Проверено запуском.** Файл `atomfast_pg_schema.sql` из этого репозитория применён к пустой базе на PostgreSQL 17.9 (aarch64) через `psql`: два применения подряд без ошибок; вставки, полученные кодом формирования пачек из прошивки (4 / 2 / 6 строк в `af_raw` / `af_agg` / `af_env`), повтор вставок не добавил строк; примеры запросов из описания схемы выполнились; логин, включённый в `af_writer`, вставляет данные, а `DELETE` ему запрещён. Вход этого логина проверялся локально внутри контейнера, не по сети.

**Не проверялось.**

- Создание групп `af_writer` и `af_reader` на сервере, где их ещё нет: на проверочном сервере они уже существовали.
- Установка PostgreSQL на Windows (установщик EDB), на конкретных дистрибутивах Linux, на Raspberry Pi, `dnf`-вариант, Docker (включая содержимое `pg_hba.conf` образа).
- Версии PostgreSQL ниже 17 (заявленная нижняя граница 14 взята из комментария в скрипте и **не проверена**; ошибка `date_trunc` ниже 14 дана по документации).
- Команды `ufw`, `firewalld`, `New-NetFirewallRule`, `pg_dump`/`pg_restore`/`pg_dumpall`, `Test-NetConnection`, `nc`, `pg_hba_file_rules`, `has_function_privilege`, запросы по `pg_authid`: даны по документации, не выполнялись.
- Строка `pg_hba.conf` и открытие порта в вашей сети.
- Вариант без права `CREATEROLE` (пункт 3.6) и прямые `GRANT` логину.
- Кодировка клиента на Windows (`PGCLIENTENCODING`).
- Как плата ведёт себя на ошибки `3D000`, `42P01`, `42501`, `23514` и другие на живой плате: описано по коду, не наблюдалось. Запись данных датчика среды на живой плате до выпуска не проверялась. Поведение позиций и повторных строк после пересоздания базы выведено из кода.
- Шаги, помеченные «только для e16k» (зависимость отправки от записи вида), на прошивке e16j не сверялись.
- Показ реальных надписей страницы в браузере: подписи взяты из файлов страницы.

Если что-то в инструкции не совпало с тем, что вы видите, откройте обращение в репозитории и приложите: версию прошивки, текст из поля «Последняя ошибка», вывод `psql --version` и вывод команды применения скрипта.
