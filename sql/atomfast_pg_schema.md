# AtomFast Gateway: структура базы PostgreSQL

Описание к файлу `atomfast_pg_schema.sql`. Прошивка 0.1.0-e16k (для 0.1.0-e16j запросы платы к БД те же). Исходный код прошивки платы в этом репозитории не опубликован; описание поведения платы ниже составлено по её коду и веб-странице.

Что делает сама плата с базой: подключается по протоколу PostgreSQL (пользователь и имя базы из её настроек), один раз за сессию вызывает `SELECT af_hwid('<MAC>'::macaddr)` и затем вставляет строки командами `INSERT INTO af_raw | af_agg | af_env ... ON CONFLICT (hwid,ring,gen,seq) DO NOTHING`. Других таблиц плата не трогает. Остальные объекты схемы (курсор, журналы, функции приёма, представления) нужны приёмнику и аналитике, плата их не использует.

## Как подключается плата

- Имена таблиц плата пишет без схемы, поэтому они должны находиться в схеме по умолчанию (`search_path`, обычно `public`).
- Значение имени базы по умолчанию в прошивке: `af_test`; меняется в настройках платы.
- Аутентификация: только SCRAM-SHA-256. Запрос шифрования (SSL) плата не отправляет, соединение идёт открытым TCP. В `pg_hba.conf` для адреса платы нужна строка `host` (не `hostssl`) с методом `scram-sha-256`.
- Какие кольца отправлять (сырые, агрегаты, среда), задаётся настройкой платы; в e16k отправляются только кольца, у которых включена запись во внутренний буфер. Схема БД от этого не зависит.

## Ключевые понятия

- `hwid` — целочисленный номер прибора в таблице `hardware`. Плата получает его вызовом `af_hwid(MAC)`; для нового MAC функция создаёт строку.
- `ring` — какое кольцо плата выгружает: 0 сырые измерения (`af_raw`), 1 агрегаты (`af_agg`), 2 датчики среды (`af_env`). В каждой таблице значение зафиксировано ограничением `CHECK`.
- `seq` — порядковый номер записи в кольце на плате (целое без знака 32 бита, поэтому в БД `bigint`).
- `epoch` — номер загрузки платы; растёт на единицу при каждом старте.
- `gen` — «поколение» данных. Плата записывает `gen = epoch`. После перезагрузки (в первую очередь после потери питания, когда кольцо восстанавливается из флеша) номера `seq` могут выдаваться заново; новый `gen` не даёт им столкнуться со старыми строками.
- Дедупликация: ключ `(hwid, ring, gen, seq)` в каждой таблице данных. Повторная отправка той же пачки в пределах одного `gen` не создаёт дублей: конфликт ключа пропускается (`ON CONFLICT DO NOTHING`), а плата сверяет, что число вставленных строк не больше числа отправленных (`af_pg_rows_ok`). Если плата перезагрузилась между первой отправкой и повторной (например, после сброса позиции отправки), повтор уйдёт под новым `gen` и может создать повторные строки; такие случаи показывает представление `af_dup_suspects`.
- Позиция (курсор) хранится на плате, в её энергонезависимой памяти, и сдвигается только после успешного ответа сервера. Одна команда `INSERT` вставляет целую пачку и выполняется как одна транзакция, поэтому при ошибке пачка не вставляется частично.
- MAC. В таблицах данных колонки MAC нет: MAC прибора (дозиметра, не шлюза) лежит только в `hardware.mac`, строки данных ссылаются на него через `hwid`. Настройка платы `csv_mac` (0 или 1, по умолчанию 1) управляет столбцом `mac` в CSV, который отдаёт веб-интерфейс платы; на структуру БД она не влияет.

## Таблицы

### hardware

Справочник приборов. Первичный ключ `id`, уникальный `mac`.

| Колонка | Тип | NULL | Смысл |
|---|---|---|---|
| id | integer, генерируется | нет | номер прибора (`hwid` в остальных таблицах) |
| mac | macaddr | нет | MAC дозиметра; уникален |
| created_at | timestamptz | нет | когда прибор появился в базе (по умолчанию `now()`) |

### af_raw (сырые измерения, ring = 0)

Первичный ключ `af_raw_pk (hwid, ring, gen, seq)`; внешний ключ `hwid -> hardware(id)`; индекс `af_raw_ts_idx (hwid, ts)`.

| Колонка | Тип | NULL | Смысл и единицы | Откуда с платы |
|---|---|---|---|---|
| seq | bigint | нет | номер записи в кольце, 0..4294967295 | поле 2 CSV (`seq`) |
| ts | timestamptz | нет | время платы (UTC); допустимо с 2020-01-01 до 2100-01-01 | поле 4 (`ts`, unix-секунды), в SQL `to_timestamp(ts)` |
| inserted_at | timestamptz | нет | когда строка попала в базу (`now()`) | заполняет сервер |
| epoch | bigint | нет | номер загрузки платы в момент чтения, справочно, в ключ не входит | поле 3 (`epoch`) |
| hwid | integer | нет | прибор | результат `af_hwid` |
| gen | integer | нет | поколение (см. выше) | `gen = epoch` платы |
| doserate | real | нет | мощность дозы, мкЗв/ч, 0..1000 | поле 7 (`doserate`) |
| dose | real | нет | накопленная доза, мЗв, не меньше 0 | поле 6 (`dose`) |
| c2s | real | нет | импульсы за 2 с, 0..65535 (в экспортном CSV поле называется `pulses_2s`) | поле 8 (`c2s`) |
| cps | real | нет | импульсов в секунду, 0..32767.5 | поле 9 (`cps`) |
| n | integer | нет | число отсчётов; для сырых всегда 1 | поле 13 (`n`) |
| ring | smallint | нет | всегда 0 | константа в запросе |
| kind | smallint | нет | для сырых всегда 0 | поле 5 (`kind`) |
| charge | smallint | нет | уровень заряда батареи прибора, целое -128..127 (единицы в коде платы не указаны) | поле 10 (`charge`) |
| t | smallint | нет | температура прибора, °C, целое -128..127 | поле 11 (`temp_c`) |
| flags | smallint | нет | флаги прибора, 0..255; в БД не расшифровываются | поле 12 (`flags`) |

Строки, не проходящие проверки (время вне диапазона, значения вне границ), плата в базу не отправляет, а пропускает и считает.

### af_agg (агрегаты по окнам, ring = 1)

Колонки и ключи те же, что у `af_raw`; индекс `af_agg_ts_idx (hwid, ts)`. Отличия:

- `ring` всегда 1.
- `kind` — длительность окна усреднения в секундах: 60..1200, кратно 60 (так же ограничено настройкой окна на плате).
- `n` — число отсчётов в окне, 1..65535.
- `ts` — время окна (начало окна по описанию схемы).
- `doserate`, `dose`, `c2s`, `cps` — значения за окно (среднее или последнее).

### af_env (датчики среды, ring = 2)

Первичный ключ `af_env_pk (hwid, ring, gen, seq)`; внешний ключ `hwid -> hardware(id)`; индексы `af_env_ts_idx (hwid, ts)` и `af_env_sensor_ts_idx (hwid, sensor, ts)`. `seq` общий для кольца среды, строки разных датчиков чередуются.

| Колонка | Тип | NULL | Смысл и единицы | Откуда с платы |
|---|---|---|---|---|
| seq, ts, inserted_at, epoch, hwid, gen | как в af_raw | нет | как в af_raw | поля 2, 4, 3 CSV, `af_hwid`, `gen = epoch` |
| press_pa | integer | да | давление, Па, 29900..110100 | поле 11 (`press_pa`); пусто в CSV означает NULL |
| temp_c | real | да | температура, °C, -40..85 | поле 8 (`temp_c`) |
| hum_pct | real | да | относительная влажность, %, 0..100 | поле 9 (`hum_pct`) |
| model | text | нет | модель датчика: bmp280, bme280, sht3x или aht2x | поле 7 (`model`); неизвестное имя плата заменяет на bmp280 |
| ring | smallint | нет | всегда 2 | константа в запросе |
| sensor | smallint | нет | номер датчика в приборе, 1..8 | поле 6 (`sensor`) |
| flags | smallint | нет | какие величины присутствуют: бит 1 температура, 2 давление, 4 коррекция, 8 влажность; допустимо 1..15 хотя бы с одним из битов 1, 2, 8 | поле 12 (`flags`) |

Связь флагов и NULL проверяется ограничением: `temp_c` не NULL тогда и только тогда, когда установлен бит 1; `press_pa` — бит 2; `hum_pct` — бит 8. Давление в мм рт. ст. в базе не хранится (`press_pa / 133.322387`).

### af_cursor (курсор приёмника)

Первичный ключ `(hwid, ring)`. Колонки: `hwid`, `ring` (0, 1 или 2), `gen`, `next_seq` (0..4294967296, следующий ожидаемый номер), `epoch`, `updated_at`. Курсор двигается функцией `af_commit_cursor`: только вперёд внутри поколения; новое поколение принимается, если его `gen` больше. Попытка сдвинуть назад вызывает ошибку `22023`. Плата эту таблицу не использует: её собственная позиция хранится в её памяти.

### af_gap (пропуски)

Колонки: `id` (генерируется), `hwid`, `ring`, `gen`, `seq_from`, `seq_to` (включительно, NULL если неизвестно), `reason` (одно из `evicted`, `regression`, `crc_skipped`, `ts_unknown`, `timeout`, `unknown`), `detected_at`, `note`. Заполняется приёмником; плата в неё не пишет.

### af_import_log (журнал загрузок)

Одна строка на пачку: `id`, `hwid`, `ring`, `gen`, `epoch`, `seq_from`, `seq_to`, `rows_in` (сколько строк пришло), `rows_new` (сколько вставлено новых), `finished_at`, `note`. Заполняется приёмником.

## Функции

- `af_hwid(macaddr) -> integer` — возвращает `id` прибора, при отсутствии создаёт строку. Это единственная функция, которую вызывает плата.
- `af_stage_prepare()`, `af_stage_env_prepare()`, `af_ingest(ring, hwid, gen, epoch, first_seq)` — приём CSV через временные таблицы и перенос в `af_raw`, `af_agg` или `af_env` с тем же `ON CONFLICT DO NOTHING`; строки с `ts = 0` не загружаются, но занимают номер `seq`.
- `af_commit_cursor(...)` — продвижение курсора (см. выше).
- `af_purge(raw_days, agg_days)` — удаляет сырые старше заданного числа суток и, если указано, агрегаты. Данные автоматически не удаляются, функцию запускает администратор.

## Представления

- `af_raw_hourly` — по часам (UTC): число отсчётов, среднее, минимум и максимум `doserate`, среднее `cps`, последняя `dose`.
- `af_agg_hourly` — по часам и по `kind`: число окон, число отсчётов, среднее `doserate` и `cps`, взвешенное по `n`, последняя `dose`.
- `af_env_hourly` — по часам, датчику и модели: средние температура, влажность, давление и число отсчётов, вошедших в каждое среднее.
- `af_dup_suspects` — строки с одинаковым содержимым и временем, но разными `gen` (подозрение на повторный импорт).

## Права

Скрипт создаёт две группы без права входа и без пароля.

- `af_writer` — для записи: `SELECT`, `INSERT` на `hardware`, `af_raw`, `af_agg`, `af_env`, `af_gap`, `af_import_log`; `SELECT`, `INSERT`, `UPDATE` на `af_cursor`; право `TEMPORARY` на базу.
- `af_reader` — только `SELECT` на таблицы и представления.

Роль, под которой плата входит в базу, создаёт администратор (с паролем по своей политике) и добавляет в `af_writer`: `GRANT af_writer TO <роль_платы>;`. Для создания групп нужно право `CREATEROLE`; если его нет, раздел «Роли» в конце скрипта можно удалить и выдать права роли платы напрямую.

## Если запись не идёт

Статус записи на плате показывает код ошибки и строку вида `<SQLSTATE>: <сообщение>`. Что делает плата:

- Сеть и сервер (классы `08`, `53`, `58`, `XX`, а также `57P01`..`57P03`, `40001`, `40P01`, `55P03`) — повтор с нарастающей паузой 1, 5, 30 и далее 120 с.
- Класс `28` (неверный пароль или роль) — запись останавливается до исправления настроек.
- Ошибки вставки (классы `22`, `23`, `42` и другие): `42P01` — таблицы нет в схеме по умолчанию (не применён скрипт или другая схема); `42501` — не хватает прав; `23514` — нарушено ограничение `CHECK`. Останавливается только то кольцо, в котором произошла ошибка.

## Примеры запросов

Последние 20 сырых измерений прибора:

```sql
SELECT r.ts, r.doserate AS "мкЗв/ч", r.cps, r.dose AS "мЗв"
FROM af_raw r JOIN hardware h ON h.id = r.hwid
WHERE h.mac = '<MAC>'::macaddr
ORDER BY r.ts DESC, r.seq DESC
LIMIT 20;
```

Пропуски в нумерации `seq` внутри одного поколения (сырые):

```sql
SELECT hwid, gen, seq + 1 AS gap_from, next_seq - 1 AS gap_to
FROM (SELECT hwid, gen, seq, lead(seq) OVER (PARTITION BY hwid, gen ORDER BY seq) AS next_seq
      FROM af_raw) s
WHERE next_seq IS NOT NULL AND next_seq > seq + 1
ORDER BY hwid, gen, seq;
```

Суточные значения по агрегатам (среднее `doserate`, взвешенное по `n`):

```sql
SELECT hwid, date_trunc('day', ts, 'UTC') AS day_utc,
       sum(n::double precision * doserate) / sum(n) AS doserate_avg,
       max(doserate) AS doserate_max
FROM af_agg
GROUP BY hwid, date_trunc('day', ts, 'UTC')
ORDER BY day_utc DESC;
```

Список приборов с объёмом данных:

```sql
SELECT h.id, h.mac, h.created_at,
       (SELECT count(*) FROM af_raw r WHERE r.hwid = h.id) AS raw_rows,
       (SELECT count(*) FROM af_agg a WHERE a.hwid = h.id) AS agg_rows,
       (SELECT count(*) FROM af_env e WHERE e.hwid = h.id) AS env_rows
FROM hardware h ORDER BY h.id;
```
